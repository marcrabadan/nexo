One language.
Two ways to run it.

Start with the interpreter while you learn. Use the compiler when you want a native program for your computer.

For the curious: what is inside?

The Python interpreter reads and executes a tree representing your program. The Rust compiler generates LLVM intermediate code, then uses clang to link a native program with Nexo’s Rust runtime.

The native runtime releases values through reference counting and uses copy on write for collections. Parallel work runs on real threads. Explore the compiler and runtime.

Nexo Shield

Your program.
Access you choose.

Shield adds permission checks. Docker can contain the run. An optional Linux worker adds restrictions enforced by the operating system.

Inspect effects before you run
nexo check --effects --require-complete app.nexo

First, inspect the permissions your code is known to need. Static analysis follows supported calls and reports policy denials and unresolved effects without executing your program. Dynamic cases can remain unknown; --require-complete makes those incomplete summaries fail the check. Shield still checks access when you run. Contain the run

A boundary around
your program.

The Shield Docker image contains native compilation and execution, with strict API checks inside.

  • Read-only source; a separate writable output.
  • Bounded memory, CPU and process count.

Docker shares the host kernel. This default mode does not add the Linux worker’s per-policy filesystem restrictions.

Restrict the worker

The operating system
enforces the boundary.

Request the Linux worker for offline work. It adds filesystem restrictions and supervised limits around the compiled program.

  • No network sockets, threads or child processes.
  • If the host cannot provide the requested guarantees, execution stops.

The worker supports a restricted synchronous profile. The operator, policy and host configuration remain trusted.

Understand the boundaries
For the curious: how are the boundaries enforced?

API checks authorize supported operations. With an explicit dependency manifest, a module and its callers can only narrow the application’s grants. Docker adds its own seccomp profile and cgroup resource limits.

The Linux worker uses openat2 to pin filesystem grants, Landlock to restrict access, seccomp to limit system calls and a pidfd supervisor to enforce a wall deadline. It requires Linux x86_64, Landlock ABI 3 or newer, the other required kernel facilities and a non-root identity. It denies all sockets, including localhost and DNS.
