Edition 0.1 · phase 5

One way to do each thing.

Nexo is a small programming language you can understand by reading it. Errors are values, money is exact, data flows through pipelines and functions state their contracts. Databases, web servers and AI come in the standard library, and the same file can describe the cloud an app runs on and how it gets there. It runs today as a Python interpreter and as a native compiler built on LLVM.

Principles

Five rules settle every design question

Nexo has a small, stable core. Anything that does not fit in it lives in an official module with the same syntax.

  1. One way to do each thing.
  2. What is safe and efficient is what you write by default; anything costly or dangerous is visible in the code.
  3. If someone with no experience cannot understand it by reading it, it does not go into the core.
  4. No keyword has two meanings.
  5. Whatever does not fit in the core lives in an official module with the same syntax.

Features

What Nexo gives you

Every snippet on this page runs with the current implementation, and the output shown under it is what it prints.

Errors are values, never hidden exceptions

A function that can fail returns T!. There are only two things you can do with a possible error: pass it up with ? or handle it on the spot with try and else e. Ignoring one is a compile error.

Missing values are a separate thing: T? and the ?? operator for a default. The two never mix.

errors.nexo
fn divide(a, b):
    if b == 0:
        fail("Cannot divide by zero")
    return a / b

try:
    print(divide(10, 4))
    print(divide(1, 0))
else e:
    print(e.message)
$ nexo --lang en errors.nexo
2.5
Cannot divide by zero

Exact decimals and money

decimal and money are built in, with currency literals such as 49.90 EUR and percentages such as 21%. Integer overflow is detected instead of wrapping silently.

split shares an amount into parts without losing a cent.

money.nexo
print(0.1 + 0.2)                  # float
price: decimal = 0.10
print(price * 3)                  # decimal: exact

total = 100.00 EUR
for part in split(total, 3):
    print(part)                   # no cent is lost
$ nexo --lang en money.nexo

0.30
33.34 EUR
33.33 EUR
33.33 EUR

Pipelines for data

Read a CSV or JSON file and shape it with where, map, pick, group by, sum, count, avg, sort by, take, each and save. Columns are used by name and it is the current row.

pipeline.nexo
sales = read("data/sales.csv")

sales
  |> where amount > 0
  |> group by region
  |> sum amount
  |> sort by amount desc
  |> take 2
  |> each print("{it["region"]}: {it["amount"]}")
$ nexo --lang en pipeline.nexo
north: 1564.5
east: 1460.0

Contracts you can read

expect states what must hold when a function is entered, ensure what must hold when it returns, and old() gives a value as it was on entry. A broken contract is a ContractBroken error showing the values involved, and it can be handled like any other error.

contracts.nexo
fn withdraw(balance: money, amount: money) -> money:
    expect amount > 0.00 EUR
    expect amount <= balance
    return balance - amount

print(withdraw(50.00 EUR, 20.00 EUR))
print(withdraw(50.00 EUR, 80.00 EUR))
$ nexo --lang en contracts.nexo
30.00 EUR
Error in contracts.nexo, line 3:
  expect amount <= balance
         ^^^^^^^^^^^^^^^^^
Unhandled error (ContractBroken): expect amount <= balance does not hold (amount = 80.00 EUR, balance = 50.00 EUR). Check the values the function receives or fix its body.

One word for your own types

type defines records, unions and enums with data, with methods inside. trait describes shared behaviour, and match takes patterns and guards.

types.nexo
type Shape:
    Circle(radius: float)
    Rect(w: float, h: float)

fn area(s: Shape) -> float:
    match s:
        Circle(r): return 3.14159 * r * r
        Rect(w, h): return w * h

shapes = [Circle(1.0), Rect(2.0, 3.0)]
print(shapes |> map area(it))
$ nexo --lang en types.nexo
[3.14159, 6.0]

Every message has the same shape: file and line, the highlighted snippet, what went wrong and how to fix it, with a "Did you mean...?" when there is a likely candidate. Messages are in Spanish by default and in English with --lang en.

Concurrency without data races

parallel for runs its tasks on threads and still gives the results, and any output, in the order of the list. use nexo.sync adds spawn, typed channels, select and shared variables. If every task ends up waiting, Nexo reports a deadlock instead of hanging.

A task may only change records it created itself, so two tasks never write to the same value.

tasks.nexo
use nexo.sync

fn produce(out: channel[int], n: int):
    for i in 1..n:
        out.send(i * i)
    out.close()

squares = channel[int](size: 2)
spawn produce(squares, 5)

var total = 0
for x in squares:
    total += x
print("sum of squares: {total}")

sizes = parallel for word in ["one", "three", "seven"]:
    return len(word)
print(sizes)
$ nexo --lang en tasks.nexo
sum of squares: 55
[3, 5, 5]

Memory without a garbage collector

Compiled programs free each value as soon as its last owner lets go of it. Lists, maps and sets are values: assigning one never lets two variables see each other's changes. Records are shared, and a weak field breaks a parent-child cycle. A cycle of ordinary fields between types is a compile error.

The race rule is checked as the program runs, and the message says what to do instead:

race.nexo
type Counter:
    n: int

counters = [Counter(1), Counter(2)]
parallel for c in counters:
    c.n += 1
$ nexo --lang en race.nexo
Error in race.nexo, line 6:
  c.n += 1
    ^
A task cannot change a Counter created before it started: other tasks may be reading it. Create the Counter inside the task, or return the change and apply it when the parallel ends.

Tests built in

test blocks and assert live next to the code. assert ... fails checks that something fails. Run them with nexo test.

Readable by default

Indentation with a colon, no braces. Immutable unless you write var. Types are optional and inferred, and required only on pub functions.

Named and default arguments

Calls always use parentheses and can name their arguments, as in Account(owner: "Ana", balance: 100.00 EUR). Builders are just named arguments.

Comprehensions and lambdas

[x * x for x in range(1, 8) if x % 2 == 1] builds a list in one line, and lambdas work wherever a function does.

Contracts the compiler proves

When the compiler can prove an ensure, it costs nothing at run time. nexo build --release --trust-ensure also drops the checks it could not prove.

One formatter, no options

nexo fmt makes all Nexo code look the same. It works on tokens and keeps your line breaks, so formatting never changes what a program does.

A linter with fixes

nexo lint warns about unused names, var that never changes, unreachable code and pipelines that never run, each with a fix. nexo fix applies the safe ones.

Your editor understands Nexo

nexo lsp gives any editor errors as you type, quick fixes, formatting, go to definition, hover and completion. The VS Code extension uses it.

A standard library for real programs

Dates, durations and time zones; find, regex and render templates; JSON and CSV with convert; an http client with retries; log, which hides @private fields.

Secrets that never leak

secret("NAME") can never be printed. password.hash, encrypt and sign are built in, and a key written in the code is a compile error.

Databases without SQL strings

With use nexo.db, @table types are the schema. Pipelines on tables become parameterised SQL on SQLite, with transactions, and nexo db diff and migrate keep the database in step.

Web servers in a block

A server block has typed routes, JWT auth, @role, @limit and secure headers. Errors become status codes, and nexo test serves the API on a free port.

AI as a function call

ask works with Anthropic, OpenAI and Ollama and checks typed answers. @tool functions and agent blocks call your code, and fake ask keeps tests offline.

C and Python when you need them

use c reads a C header and calls its functions. use python imports a Python module, so existing libraries stay within reach.

Infrastructure in the same file

infra blocks declare apps, databases, storage, queues, networks and identities once, for AWS, Azure, GCP or Kubernetes. nexo plan shows the changes, the cost and the availability; apply, drift, destroy and import talk to each cloud's own API.

Pipelines that are ordinary code

The steps of a pipeline are Nexo code with run, test(), build_image, approve and apply. nexo ci run runs it on your machine and nexo ci export writes the GitHub, GitLab, Azure or Jenkins file.

Streams, flags and privacy

when kafka("orders") as msg handles messages with retries and dead letters, with window steps in pipelines. flags roll features out by percentage or audience, and @personal and @private fields are kept, encrypted and erased by rule.

Two implementations, one output

The interpreter and the compiler run the same conformance suite and a differential test, and must print the same thing for every program.

Accounts guarded by expect, ensure and old(); a broken contract is an error that can be handled.

examples/bank.nexo
## Bank accounts with contracts: expect, ensure and old() guard every
## operation, and a broken contract is an error that can be handled.

type Account:
    owner: str
    balance: money

fn deposit(account: Account, amount: money):
    expect amount > 0.00 EUR
    ensure account.balance == old(account.balance) + amount

    account.balance += amount

fn transfer(source: Account, target: Account, amount: money):
    expect amount > 0.00 EUR
    expect source.balance >= amount
    ensure source.balance + target.balance == old(source.balance + target.balance)

    source.balance -= amount
    target.balance += amount

ana = Account(owner: "Ana", balance: 100.00 EUR)
luis = Account(owner: "Luis", balance: 20.00 EUR)

deposit(ana, 50.00 EUR)
transfer(ana, luis, 70.00 EUR)
print("{ana.owner}: {ana.balance}")
print("{luis.owner}: {luis.balance}")

try:
    transfer(luis, ana, 500.00 EUR)
else e is ContractBroken:
    print("Rejected: {e.message}")

try:
    deposit(ana, -5.00 EUR)
else e is ContractBroken:
    print("Rejected: {e.message}")

test "a transfer keeps the total":
    a = Account(owner: "A", balance: 10.00 EUR)
    b = Account(owner: "B", balance: 0.00 EUR)
    transfer(a, b, 4.00 EUR)
    assert a.balance == 6.00 EUR
    assert b.balance == 4.00 EUR

test "cannot transfer more than the balance":
    a = Account(owner: "A", balance: 1.00 EUR)
    b = Account(owner: "B", balance: 0.00 EUR)
    assert transfer(a, b, 2.00 EUR) fails
$ nexo --lang en bank.nexo
Ana: 80.00 EUR
Luis: 90.00 EUR
Rejected: expect source.balance >= amount does not hold (source.balance = 90.00 EUR, amount = 500.00 EUR)
Rejected: expect amount > 0.00 EUR does not hold (amount = -5.00 EUR)

Records with methods, an enum, a trait and match with guards.

examples/grades.nexo
## Grade book: records with methods, an enum, match with guards and a trait.

trait Describable:
    fn describe(self) -> str

type Grade:
    Excellent
    Good
    Pass
    Fail

type Student is Describable:
    name: str
    scores: list[int]

    fn average(self) -> float:
        return self.scores.sum() / len(self.scores)

    fn describe(self) -> str:
        return "{self.name} ({len(self.scores)} exams)"

fn grade(avg: float) -> Grade:
    match avg:
        a if a >= 9: return Excellent
        a if a >= 7: return Good
        a if a >= 5: return Pass
        _: return Fail

fn label(g: Grade) -> str:
    match g:
        Excellent: return "excellent"
        Good: return "good"
        Pass: return "pass"
        Fail: return "fail"

students = [
    Student("Ana", [9, 10, 9]),
    Student("Luis", [6, 7, 5]),
    Student("Eva", [4, 3, 6]),
    Student("Marc", [8, 7, 9])
]

for s in students:
    avg = s.average()
    print("{s.describe()}: {round(avg, 1)} -> {label(grade(avg))}")

passed = students |> where grade(it.average()) != Fail |> count
print("Passed: {passed} of {len(students)}")

ranking = students |> sort by it.average() desc |> map name
print("Ranking: {ranking}")

test "grades follow the average":
    assert grade(9.5) == Excellent
    assert grade(7.0) == Good
    assert grade(4.9) == Fail

test "average of a student":
    assert Student("X", [5, 7]).average() == 6.0
$ nexo --lang en grades.nexo
Ana (3 exams): 9.3 -> excellent
Luis (3 exams): 6.0 -> pass
Eva (3 exams): 4.3 -> fail
Marc (3 exams): 8.0 -> good
Passed: 3 of 4
Ranking: ["Ana", "Marc", "Luis", "Eva"]

The exit criterion of phase 4: a web API with a database and ask, written in Nexo alone. Its tests fake the AI, so they run without a key.

examples/shop_api/shop.nexo
# A shop's web API with a database and AI, written in Nexo alone (the exit
# criterion of phase 4). Run it with
#     SHOP_JWT_KEY=... ANTHROPIC_KEY=... nexo shop.nexo
# and test it, with the AI faked, with `nexo test shop.nexo`.
use nexo.db

db = connect("shop.db")
tokens = jwt(key: secret("SHOP_JWT_KEY"))

ai:
    provider = "anthropic"
    model = "claude-opus"
    key = secret("ANTHROPIC_KEY")

@table
type Product:
    id: id
    name: str @unique
    price: decimal

@table
type Review:
    id: id
    product: ref Product
    text: str
    tone: str
    score: int

type NewProduct:
    name: str
    price: decimal

type NewReview:
    text: str

type Opinion:
    tone: "positive" | "negative" | "neutral"
    score: 1..5

## What the AI thinks of a review: its tone and a score from 1 to 5.
fn opinion(text: str) -> Opinion!:
    o: Opinion = ask("Analyse this review of a product", text, creativity: low)?
    return o

## A short summary of the reviews of a product.
fn summary(reviews: list[Review]) -> str!:
    if len(reviews) == 0:
        return "No reviews yet."
    texts = reviews |> map it.text
    return ask("Summarise these reviews in one sentence", texts, max: 40 words)?

server shop:
    port = 8080
    auth = tokens

    @public
    post "/login"(name: str):
        return {"token": tokens.sign({"sub": name, "role": "admin"}, expires: 1h)}

    @public
    get "/products"():
        return db.Product |> sort by name

    @public
    get "/products/{id}"(id: int):
        return db.Product.find(id: id)?

    @role("admin")
    post "/products"(product: NewProduct):
        return db.Product.add(name: product.name, price: product.price)

    @public
    @limit(10 per minute per ip)
    post "/products/{id}/reviews"(id: int, review: NewReview):
        product = db.Product.find(id: id)?
        o = opinion(review.text)?
        return db.Review.add(product: product, text: review.text, tone: o.tone, score: o.score)

    @public
    get "/products/{id}/summary"(id: int):
        product = db.Product.find(id: id)?
        reviews = db.Review |> where product == product
        scores = reviews |> map it.score
        var average = 0.0
        if len(scores) > 0:
            average = float(scores |> sum) / len(scores)
        return {"product": product.name, "reviews": len(scores), "score": average, "summary": summary(reviews)?}

test "products need an admin":
    try:
        http.post("{shop.url}/products", {"name": "Lamp", "price": 25}, retries: 0)
    else e is HTTPError:
        assert e.message.ends_with("401 Unauthorized")
    login = http.post("{shop.url}/login?name=ana", none).json()
    headers = {"Authorization": "Bearer {login["token"]}"}
    lamp = http.post("{shop.url}/products", {"name": "Lamp", "price": 25.50}, headers: headers)
    assert lamp.status == 201
    assert lamp.json()["name"] == "Lamp"
    assert http.get("{shop.url}/products").json()[0]["price"] == 25.5

test "reviews are analysed by the AI":
    fake ask returns Opinion(tone: "positive", score: 5)
    login = http.post("{shop.url}/login?name=ana", none).json()
    headers = {"Authorization": "Bearer {login["token"]}"}
    chair = http.post("{shop.url}/products", {"name": "Chair", "price": 80}, headers: headers).json()
    review = http.post("{shop.url}/products/{chair["id"]}/reviews", {"text": "Comfortable!"}).json()
    assert review["tone"] == "positive" and review["score"] == 5
    fake ask returns "Buyers love it."
    s = http.get("{shop.url}/products/{chair["id"]}/summary").json()
    assert s["summary"] == "Buyers love it." and s["reviews"] == 1 and s["score"] == 5.0

test "a missing product is a 404":
    try:
        http.get("{shop.url}/products/999", retries: 0)
    else e is HTTPError:
        assert e.message.ends_with("404 Not Found")
$ SHOP_JWT_KEY=... nexo --lang en test shop.nexo
✓ products need an admin
✓ reviews are analysed by the AI
✓ a missing product is a 404
3 tests: 3 passed, 0 failed

The exit criterion of phase 5: one file holds an app, its tests, the four places it runs (AWS, Azure, GCP and Kubernetes) and the pipeline that builds and deploys it. The app on Kubernetes reads the database on GCP, so nexo apply deploys GCP first.

examples/deploy/shop.nexo
# The exit criterion of phase 5: one file holds an app, the four places it
# runs (AWS, Azure, GCP and Kubernetes) and how it gets there.
#     nexo shop.nexo                serves it on port 8080
#     nexo test shop.nexo           runs its tests
#     nexo plan / nexo apply        deploys it to the four targets
#     nexo ci run --yes             builds its image and deploys it
#     nexo ci export github         writes the workflow that does the same

flags:
    express_shipping = 20%

type Order:
    item: str
    quantity: int

## The price of shipping an order: express for some users (a flag).
fn shipping(order: Order, user: str) -> money:
    if flag("express_shipping", user):
        return 4.90 EUR
    return 2.50 EUR + 0.10 EUR * order.quantity

test "shipping grows with the quantity":
    assert shipping(Order(item: "tea", quantity: 1), "nobody") <= shipping(Order(item: "tea", quantity: 3), "nobody")

server shop:
    port = 8080

    @public
    get "/health":
        return {"ok": true}

    @public
    post "/orders"(order: Order, user: str):
        return {"item": order.item, "shipping": shipping(order, user)}

infra shop_aws:
    cloud = "aws"

    budget = 200 EUR per month
    network net:

            DB = orders.url
            API_KEY = secret("API_KEY")

infra shop_azure:

infra shop_gcp:
    cloud = "gcp"

Get started

Run your first Nexo program

Nexo is not packaged yet, so you run it from a clone of the repository. The interpreter needs Python 3.12; the compiler also needs Rust (cargo) and clang.

1Install the interpreter

Clone the repository and install it in a virtual environment.

shell
git clone https://github.com/marcrabadan/nexo.git
cd nexo
python3.12 -m venv .venv
.venv/bin/pip install -e '.[dev]'

2Write and run a program

Save this as hello.nexo and run it, or start the REPL with .venv/bin/nexo.

hello.nexo
name = "world"
print("Hello, {name}!")
$ nexo --lang en hello.nexo
Hello, world!

3Try the everyday commands

shell
# run a program
.venv/bin/nexo examples/invoice.nexo
# messages in English
.venv/bin/nexo --lang en app.nexo
# run the test blocks
.venv/bin/nexo test examples/
# format, lint and apply the safe fixes
.venv/bin/nexo fmt app.nexo
.venv/bin/nexo lint app.nexo
.venv/bin/nexo fix app.nexo
# interactive REPL
.venv/bin/nexo

4Compile to native code

The compiler generates LLVM IR and links it with a small runtime library that frees memory by reference counting and runs parallel on threads.

shell
cd compiler && cargo build --release && cd ..
compiler/target/release/nexo examples/invoice.nexo
compiler/target/release/nexo build --release app.nexo -o app
./app

Roadmap

Where Nexo is today

Nexo is built in phases, and each one ends with something usable. The specification describes the whole language, including modules such as machine learning, user interfaces and notifications that are not implemented yet. Every choice made where it was ambiguous is recorded in docs/decisions.md.

PhaseDeliverableStatus
0. PrototypePython tree-walking interpreter for the coreDone
1. Base compilerRust compiler: lexer, parser, gradual type checking, LLVM code generationDone
2. Memory and concurrencyMemory model, real parallel, nexo.sync, contracts the compiler provesDone
3. Toolingnexo fmt, lint, fix, check, lsp, a REPL in the compiler, the VS Code extension, a fix for every errorDone
4. Library and modulesStandard library, nexo.ai, nexo.web, nexo.db, C and Python interopDone
5. Cloud and operationsnexo.infra for AWS, Azure, GCP and k8s, nexo.ci, nexo.stream, feature flags, privacyDone
6. Optimisation and 1.0Performance goals, external audit, user studiesPlanned
7. Self-hostingThe compiler rewritten in NexoPlanned

How fast is it?

Phase 2 aimed for compiled programs within 2× the time of the same program in Rust. compiler/bench/compare.py measures this on each benchmark. Code on integers already meets that goal. Code on lists, maps and records does not yet, because every value there is boxed and reference-counted.
