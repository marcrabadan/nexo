Nexo 0.1 · Read the specification

The language humans read and AI agents get right.

Nexo is a new programming language with one way to do each thing. Errors can’t be ignored, money is exact, permissions are declared and every compiler message tells you how to fix it. The code you write — and the code your agent writes — is correct sooner.

Try it in your browser Install in two minutes

Run it on the interpreter or compile it to native code with LLVM.Two implementations, checked against each other on every program.

orders.nexo
type Order:
    customer: str
    total: money

fn charge(order: Order) -> money!:
    expect order.total > 0 EUR
    if order.customer == "":
        fail("Order without a customer")
    return order.total + order.total * 21%

orders = [
    Order("Ada", 120.00 EUR),
    Order("", 35.50 EUR),
    Order("Grace", 210.00 EUR)
]

big = orders |> where total > 100 EUR |> map it.customer
print("Big orders: {big}")

for order in orders:
    try:
        paid = charge(order)
        print("Charged {order.customer}: {paid}")
    else e:
        print("Skipped: {e.message}")
Output
Big orders: ["Ada", "Grace"]
Charged Ada: 145.20 EUR
Skipped: Order without a customer
Charged Grace: 254.10 EUR

The problem

Shipping one service takes five languages and a pile of YAML.

Application code, SQL, Terraform, a CI file, a Dockerfile and the scripts that glue them together — each with its own syntax, its own way of failing and its own security model.

AI agents make the gaps wider. When a language offers ten ways to do something, a model picks one that looks plausible. When errors hide in exceptions and permissions live in a wiki, nobody notices until production.

Nexo puts the application, its data, its infrastructure, its pipeline and its permissions in one readable language — with one way to write each of them.

Why developers choose Nexo

Safe by default. Readable on purpose.

What is safe and efficient is what you write by default. Anything costly or dangerous is always visible in the code.

  • Readable first

    Indentation, named arguments and plain words. If someone new to programming can’t follow it, it doesn’t go into the core.

  • Errors are values

    A function that can fail returns T!. Pass it up with ? or handle it with try. Ignoring it is a compile error.

  • Exact money and numbers

    49.90 EUR, 21% and split(total, 3) never lose a cent. Integer overflow is detected, not wrapped.

  • Pipelines built in

    where, map, group by, sum work on lists — and on database tables, translated to SQL.

  • Contracts the compiler proves

    expect, ensure and old(). What the compiler can prove costs nothing; the rest is checked at run time.

  • Concurrency without races

    parallel for on real threads. Data races are compile errors. Reference counting and copy-on-write: no GC pauses, no manual memory.

Errors that teach

Every message ends with the fix.

Nexo’s compiler says where the problem is, what went wrong and what to do about it, in plain English. nexo fix applies the safe fixes for you, and your editor offers them as quick fixes through the language server.

For a person, that’s a shorter debugging session. For an agent, it’s a loop it can close on its own.

fn divide(a, b):
    if b == 0:
        fail("Cannot divide by zero")

fn half(x):
    return divide(x, 2)

Built for AI agents

Your coding agent’s favourite language.

Models write the most reliable code when there is one obvious way to do things, the available API is explicit and the compiler answers in words. Nexo was designed around that loop — and gives your agent the tools to run it.

  1. 01 · Ground

    Know what exists

    nexo docs --for-ai prints the exact functions a program can use. No guessing, no hallucinated APIs. llms.txt gives the rest of the docs on demand.

  2. 02 · Check

    Validate before running

    nexo check --json returns structured diagnostics, each with its fix. nexo check --intent compares ## comments and contracts with what the code does.

  3. 03 · Repair

    Apply the safe fixes

    nexo fix and nexo fmt leave one canonical version of the code, so diffs stay small and reviews stay quick.

  4. 04 · Prove

    Test the edge cases

    nexo test --suggest proposes cases from types, contracts and unions; --coverage shows which branches ran.

Plug Nexo into your assistant with MCP

nexo mcp is a Model Context Protocol server. It gives any MCP-capable assistant check, run_tests, docs_for_ai, plan and format — and never apply, so infrastructure changes always wait for a person.

Code your agent writes runs inside the policy you declared: it can’t reach files, hosts or commands you didn’t allow.

Secure by design

Permissions you can read in the code.

  • A program policy. Files, network, environment, shell, C and Python: allowed by name, checked by the standard library before every access.
  • A hardened supply chain. Release builds are identical byte for byte and come with a CycloneDX SBOM. Packages are signed with Ed25519 and pinned in nexo.lock.
  • Unsafe code you can find. nexo audit lists every use of C in your program and its packages.
  • Isolation when you need it. Nexo Shield adds dependency ceilings, an offline Linux worker and a hardened container profile.

A policy limits Nexo’s own APIs; it isn’t an OS sandbox. Shield explains exactly what each profile does and doesn’t enforce. Read the security model

Honest by design

Every promise comes with its evidence.

The specification states each guarantee together with how it is verified. A public page tracks every one as met, not met or needs people — an external audit, a user study, a registry. A guarantee that fails in testing is fixed or removed.

Install & run

Your first program,
on your computer.

You need a macOS or Linux terminal with Git and Python 3.12. You’ll download Nexo and run the interpreter, which reads and executes your code. No install? Use the playground.

1. Set up Nexo

Download the source and install it in a virtual environment: a separate place for this project’s Python packages.

Terminal
git clone https://github.com/marcrabadan/nexo.git
cd nexo
python3.12 -m venv .venv
.venv/bin/pip install -e .

Keep this terminal open in the nexo folder for the next steps. Using VS Code? Install the Nexo extension and point its nexo.path setting to the CLI.

2. Save your first file

In your text editor, create hello.nexo inside the nexo folder and paste these two lines.

hello.nexo
name = "Ada"
print("Hello, {name}!")

3. Run it

Back in the terminal, enter this command.

Terminal
.venv/bin/nexo hello.nexo
Output
Hello, Ada!
Now learn what each line does

Want native code? See the two ways to run a program and the compiler commands for building a release binary with its SBOM.
