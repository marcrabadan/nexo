Edition 0.1 · Read the specification

One way to do each thing, checked by the compiler.

Nexo is a statically checked language with errors as values (T!), exact decimal and money types, reference counting with copy-on-write, race-free parallel, and contracts the compiler proves where it can. Its compiler emits diagnostics as JSON with machine-applicable fixes, so humans and coding agents iterate on the same signal.

Run it in the browser Install

Two implementations: a tree-walking interpreter in Python 3.12 and an LLVM compiler in Rust.Conformance, differential and fuzz tests require identical output from both.

orders.nexo
type Order:
    customer: str
    total: money

fn charge(order: Order) -> money!:
    expect order.total > 0 EUR
    if order.customer == "":
        fail("Order without a customer")
    return order.total + order.total * 21%

orders = [
    Order("Ada", 120.00 EUR),
    Order("", 35.50 EUR),
    Order("Grace", 210.00 EUR)
]

big = orders |> where total > 100 EUR |> map it.customer
print("Big orders: {big}")

for order in orders:
    try:
        paid = charge(order)
        print("Charged {order.customer}: {paid}")
    else e:
        print("Skipped: {e.message}")

Design rules

Five rules settle every design question.

From section 1 of the specification. Where an earlier draft had two ways to do something, edition 0.1 keeps one, and every resolved ambiguity is recorded with its reason in docs/decisions.md.

  1. One way to do each thing.
  2. What is safe and efficient is the default; anything costly or dangerous is visible in the code.
  3. If someone with no experience cannot read it, it does not go into the core.
  4. No keyword has two meanings.
  5. What does not fit in the core is an official module with the same syntax.

Semantics

What the language guarantees.

Small core, explicit costs. Both implementations enforce the same rules, and the leak checker (NEXO_LEAKCHECK=1) runs on every test suite.

  • Errors as values

    A fallible function returns T!, inferred and written out on pub functions. ? propagates; try … else e handles, optionally by kind (else e is NotFound). Discarding a T! is a compile error. Missing values are a separate type, T? with ??.

  • Numeric tower

    int is 64-bit and fails with an Overflow error instead of wrapping. decimal is exact; money carries its currency and refuses to mix currencies; unit literals (5 km, 30s, 21%) are checked. split(money, n) distributes the remainder so the parts sum exactly.

  • Memory model

    Reference counting, no tracing GC. Lists, maps and sets are copied on write; records are shared. Back-references use weak T? fields, and a cycle of strong references between types is a compile error.

  • Concurrency

    parallel for and parallel: run on OS threads; results and output come back in task order. Shared mutable state across tasks is rejected at compile time. nexo.sync adds spawn, channel, select and shared.

  • Contracts

    expect, ensure and old(). A proven contract costs nothing at run time; an unproven one is checked and fails with ContractBroken and the values involved. Release builds keep every expect; --trust-ensure drops unproven ensure checks.

  • Pipelines

    where, map, pick, group by, sort by, sum, count with it and bare column names. On lists they fuse into one loop; on nexo.db tables they are translated to parameterised SQL.

Toolchain

One front end, two back ends.

The same grammar (the EBNF of section 24), the same checks and the same message catalog feed an interpreter for fast iteration and a compiler for production. A change that makes them disagree fails the build.

  1. Front end

    Lexer and parser

    Indentation as INDENT/DEDENT tokens, unit literals and string interpolation; recursive descent that follows the EBNF. Module blocks such as policy: or infra are lowered to ordinary builtin calls.

  2. Phase 0 · Python

    Interpreter

    A static pre-pass for compile errors, then a tree-walking evaluator. Runs everywhere Python 3.12 runs, including the browser playground on Pyodide.

  3. Phase 1 · Rust

    Compiler

    Scope and closure resolution, gradual type checking, narrowing of ints and records of known types, then LLVM IR compiled by clang and linked against a static runtime. Targets native code and wasm32-wasip1.

  4. Verification

    Same output, always

    A conformance suite of .nexo/.expected pairs, a differential test against phase 0, and a fuzzer generating random programs for both — 500 more every night.

Also in the box: nexo fmt (token-preserving, no options), nexo lint and nexo fix, a language server, a REPL, nexo test --coverage for branch coverage and a VS Code extension. Read the architecture

Diagnostics

Errors with a fix, for terminals and for tools.

Every diagnostic has a location, a highlighted snippet, what went wrong and how to fix it. nexo check --json returns the same data in a versioned, LSP-shaped schema with text edits; nexo fix applies those marked safe.

nexo half.nexo
fn divide(a, b):
    if b == 0:
        fail("Cannot divide by zero")
    return a / b

fn half(x):
    return divide(x, 2)

print(half(10))
stderr

Built for AI agents

A closed loop: ground, check, repair, test.

LLMs fail on languages with many equivalent idioms and on APIs they have to guess. Nexo removes the first by design and the second with a machine-readable API surface, and exposes the compiler to the agent over MCP.

nexo mcp: a Model Context Protocol server on stdio

Each tool runs the same nexo binary on a path inside the project; absolute paths and escapes through .. or symlinks are refused. Deployments, apply and secrets are never exposed.

  1. 01 · Ground

    Exact API surface

    nexo docs --for-ai prints every callable from nexo/stdlib/api.json, which a test keeps equal to the builtins of both runtimes, plus the file’s own declarations. llms.txt indexes the rest.

  2. 02 · Check

    Compile without running

    Structured diagnostics with edits. nexo check --intent asks the configured model whether each function matches its ## comments and contracts.

  3. 03 · Repair

    Canonical output

    nexo fix applies safe edits; nexo fmt has no options, so the same program always has the same text and diffs stay minimal.

  4. 04 · Test

    Generated edge cases

    nexo test --suggest derives cases from types, contracts and unions; on the reference program it lifts branch coverage from 20% to 100%.

Security model

Capabilities in the source, enforced at the API boundary.

  • Program policy. read, write, net, env, shell, c and python, checked by the standard library before each access in both runtimes. Release builds refuse what is not allowed; development mode warns once.
  • Supply chain. Byte-identical release builds with a CycloneDX SBOM. Ed25519-signed packages pinned by version, sha256 and key in nexo.lock; declared [permissions] are checked against your policy at install time.
  • Auditable unsafe. use c is the only unsafe code in this edition, and nexo audit lists every use.
  • Kernel isolation, opt-in. Nexo Shield’s Linux worker applies Landlock, a seccomp allowlist and hard resource limits, and denies sockets and child processes; a read-only, non-root container profile is also available.

The policy governs Nexo APIs; it does not mediate direct native syscalls or DNS rebinding. Those need a Shield profile. Threat model and limits

Performance

Native code, measured against Rust.

Fields of known record types are read by index and methods called directly; small records are one allocation; range loops are counted; where/map/sum pipelines fuse into a single loop; maps have a dedicated int-key table; short strings are stored inline; freed objects are reused from a per-thread pool; reference counts skip atomics until a second thread starts.

Against Rust (rustc -O, overflow checks on): records 0.27×, strings 1.20×, lists 1.30×, parallel 1.35×, maps 1.44×. The goal is under 1.5× everywhere; loop (1.52×) and fib (1.63×) do not meet it yet. Memory is at or below Rust’s on seven of eight benchmarks.

Same syntax from the API to the cluster.

Evidence

Every guarantee states how it is verified.

The specification pairs each guarantee with its verification method. docs/guarantees.md tracks each one as met, not met or needs people (an external audit, a user study, a public registry), with the script or test that produces the number. A guarantee that fails in testing is fixed or removed from the specification.

Not done yet: an external audit of the compiler and crypto, user studies, the public package registry, and a benchmark of first-try success rates for LLM-generated programs.

Install & run

Build from source.

The interpreter needs Python 3.12 on macOS or Linux. The compiler additionally needs cargo and clang. No install? Use the playground.

1. Interpreter

Clone the repository and install the CLI in a virtual environment.

Terminal
git clone https://github.com/marcrabadan/nexo.git
cd nexo
python3.12 -m venv .venv
.venv/bin/pip install -e .

VS Code: install the Nexo extension and set nexo.path to the CLI.

2. Run a program

Create hello.nexo in the nexo folder.

hello.nexo
name = "Ada"
print("Hello, {name}!")
Terminal
.venv/bin/nexo hello.nexo
Output
Hello, Ada!

3. Compile to native (optional)

Build the native toolchain, then compile the same file to a release binary with its SBOM.

Terminal
cd compiler && cargo build && cd ..
compiler/target/debug/nexo build --release hello.nexo -o hello
