One way to do each thing.

Nexo is a small programming language you can understand by reading it. Errors are values, money is exact, data flows through pipelines and functions state their contracts. Databases, web servers and AI come in the standard library, and the same file can describe the cloud an app runs on and how it gets there.

Principles

Five rules settle every design question

Nexo has a small, stable core. Anything that does not fit in it lives in an official module with the same syntax.

  1. One way to do each thing.
  2. What is safe and efficient is what you write by default; anything costly or dangerous is visible in the code.
  3. If someone with no experience cannot understand it by reading it, it does not go into the core.
  4. No keyword has two meanings.
  5. Whatever does not fit in the core lives in an official module with the same syntax.

Features

What Nexo gives you

Every snippet here runs with the current implementation, and the output shown under it is what it prints.

Errors are values, never hidden exceptions

A function that can fail returns T!. There are only two things you can do with a possible error: pass it up with ? or handle it on the spot with try and else e. Ignoring one is a compile error.

Missing values are a separate thing: T? and the ?? operator for a default. The two never mix.

errors.nexo
fn divide(a, b):
    if b == 0:
        fail("Cannot divide by zero")
    return a / b

try:
    print(divide(10, 4))
    print(divide(1, 0))
else e:
    print(e.message)
$ nexo errors.nexo
2.5
Cannot divide by zero

Pipelines for data

Read a CSV or JSON file and shape it with where, map, pick, group by, sum, count, avg, sort by, take, each and save. Columns are used by name and it is the current row.

Contracts you can read

expect states what must hold when a function is entered, ensure what must hold when it returns, and old() gives a value as it was on entry. A broken contract is a ContractBroken error showing the values involved, and it can be handled like any other error.

contracts.nexo
fn withdraw(balance: money, amount: money) -> money:
    expect amount > 0.00 EUR
    expect amount <= balance
    return balance - amount

print(withdraw(50.00 EUR, 20.00 EUR))
print(withdraw(50.00 EUR, 80.00 EUR))
$ nexo contracts.nexo

One word for your own types

type defines records, unions and enums with data, with methods inside. trait describes shared behaviour, and match takes patterns and guards.

types.nexo
type Shape:
    Circle(radius: float)
    Rect(w: float, h: float)

fn area(s: Shape) -> float:
    match s:
        Circle(r): return 3.14159 * r * r
        Rect(w, h): return w * h

shapes = [Circle(1.0), Rect(2.0, 3.0)]
print(shapes |> map area(it))
$ nexo types.nexo
[3.14159, 6.0]

Concurrency without data races

parallel for runs its tasks on threads and still gives the results, and any output, in the order of the list. use nexo.sync adds spawn, typed channels, select and shared variables. If every task ends up waiting, Nexo reports a deadlock instead of hanging.

A task may only change records it created itself, so two tasks never write to the same value.

tasks.nexo
use nexo.sync

fn produce(out: channel[int], n: int):
    for i in 1..n:
        out.send(i * i)
    out.close()

squares = channel[int](size: 2)
spawn produce(squares, 5)

var total = 0
for x in squares:
    total += x
print("sum of squares: {total}")

sizes = parallel for word in ["one", "three", "seven"]:
    return len(word)
print(sizes)
$ nexo tasks.nexo
sum of squares: 55
[3, 5, 5]

Memory without a garbage collector

Compiled programs free each value as soon as its last owner lets go of it. Lists, maps and sets are values: assigning one never lets two variables see each other's changes. Records are shared, and a weak field breaks a parent-child cycle. A cycle of ordinary fields between types is a compile error.

The race rule is checked as the program runs, and the message says what to do instead:

race.nexo
type Counter:
    n: int

counters = [Counter(1), Counter(2)]
parallel for c in counters:
    c.n += 1
$ nexo race.nexo
Error in race.nexo, line 6:
  c.n += 1
    ^
A task cannot change a Counter created before it started: other tasks may be reading it. Create the Counter inside the task, or return the change and apply it when the parallel ends.

Databases without SQL strings

With use nexo.db, @table types are the schema, and ref and many are the relations between them. A pipeline on a table, such as db.Order |> where amount > 100, becomes one parameterised SQL query on SQLite.

Everything inside db.transaction: is kept or undone together: the second customer breaks @unique, so the order added before it is rolled back too. nexo db diff and nexo db migrate keep the database in step with the types.

orders.nexo
use nexo.db

db = connect("shop.db")

@table
type Customer:
    id: id
    name: str
    email: str @unique
    orders: many Order

@table
type Order:
    id: id
    customer: ref Customer
    amount: float

ana = db.Customer.add(name: "Ana", email: "ana@mail.com")
db.Order.add(customer: ana, amount: 49.9)
db.Order.add(customer: ana, amount: 150.0)

large = db.Order |> where amount > 100 |> map it.amount
print(large)
print(ana.orders.count(), ana.orders |> map it.amount |> sum)

try:
    db.transaction:
        db.Order.add(customer: ana, amount: 1.0)
        db.Customer.add(name: "Copy", email: "ana@mail.com")
else e:
    print(e.message)
print(db.Order.count())
$ nexo orders.nexo

2 199.9

A web API in a block

A server block has typed routes: {n} arrives as an int and a body as an Item, and anything else is a 400. Returning a number answers with that status, and errors become status codes.

auth = jwt(...) protects every route that is not @public, and @role asks for a role in the token. Under nexo test the server answers on a free port, at shop.url.

api.nexo
tokens = jwt(key: password.generate(32))

type Item:
    name: str
    price: decimal

items = [Item(name: "pen", price: 1.50)]

server shop:
    port = 8080
    auth = tokens

    @public
    get "/items/{n}"(n: int):
        if n >= len(items):
            return 404
        return items[n]

    @role("admin")
    post "/items"(item: Item):
        return item

test "routes answer JSON":
    assert http.get("{shop.url}/items/0").json()["name"] == "pen"

test "errors become status codes":
    try:
        http.get("{shop.url}/items/9", retries: 0)
    else e is HTTPError:
        print(e.message.replace(shop.url, ""))
    try:
        http.post("{shop.url}/items", {"name": "cup", "price": 2}, retries: 0)
    else e is HTTPError:
        print(e.message.replace(shop.url, ""))
$ nexo test api.nexo
✓ routes answer JSON
GET /items/9 answered 404 Not Found
POST /items answered 401 Unauthorized
✓ errors become status codes
2 tests: 2 passed, 0 failed

AI as a function call

ask sends an instruction and an input to the configured model (Anthropic, OpenAI or Ollama, set up with nexo ai setup or an ai: block). With a declared type the answer is that type, checked field by field, so score is always between 1 and 5.

fake ask returns ... replaces the model inside a test, so tests run offline and without a key. @tool functions and agent blocks let the model call your code.

reviews.nexo
type Opinion:
    tone: "positive" | "negative" | "neutral"
    score: 1..5

fn classify(review: str) -> Opinion!:
    o: Opinion = ask("Analyse this review", review)?
    return o

fn summary(text: str) -> str!:
    return ask("Summarise this text", text, max: 20 words, creativity: low)?

test "a typed answer":
    fake ask returns Opinion(tone: "positive", score: 4)
    assert classify("Great!").score == 4

test "a short summary":
    fake ask returns "A short text."
    assert summary("A very long text") == "A short text."
$ nexo test reviews.nexo
✓ a typed answer
✓ a short summary
2 tests: 2 passed, 0 failed

Secrets that never leak

The algorithms are chosen for you: Argon2id for password.hash, AES-256-GCM for encrypt and Ed25519 for sign. There is nothing to configure wrongly.

secret("NAME") reads a secret from the environment. It can be passed where it is needed, such as a key or a header, but never printed, logged or written to a file. A key written in the code is a compile error.

secrets.nexo
stored = password.hash("hunter2")
print(password.check("hunter2", stored), password.check("hunter3", stored))

k = key.new()
hidden = encrypt("Ana's card", k)
print(decrypt(hidden, k))

pair = keypair.new()
signature = sign("contract v1", pair.private)
print(verify("contract v1", signature, pair.public), verify("contract v2", signature, pair.public))

db_pass = secret("DB_PASSWORD")
print("the password is {db_pass}")
$ nexo secrets.nexo
true false
Ana's card
true false
Error in secrets.nexo, line 13:
  print("the password is {db_pass}")
                          ^^^^^^^
A secret cannot be shown or turned into text. Pass the secret only where it is needed (key: ..., a connect password, an http header); never to print, str() or a file.

regex leaves out lookarounds and backreferences, so a pattern matches the same in both implementations. convert turns records into CSV or JSON, and changing currency needs an explicit rate.

C and Python when you need them

Calls into C are the only unsafe code in this edition, and nexo audit lists every one of them.

Pipelines that are ordinary code

The steps of a pipeline are Nexo code with test(), run, build_image, approve and apply, and a variable set in one step is seen by the next.

nexo ci run runs it on your machine, asking for each approval (--yes gives them). nexo ci export github, gitlab, azure or jenkins writes the file that runs the same steps in CI.

app.nexo
fn total(prices: list[int]) -> int:
    return prices |> sum

test "the total adds the prices":
    assert total([2, 3]) == 5

pipeline main:
    trigger push to main
    version = "1.4.0"

    step checks:
        test()

    step build:
        image = "shop:{version}"
        run("echo building {image}")

    step prod:
        approve(by: ["ana@shop.example", "luis@shop.example"])
        print("deploying", image)

    after success:
        print("v{version} is live")

Streams are another source

when kafka("orders") as msg handles each message. A message that fails is tried again and then goes to the dead letters, and a key makes sure the same order is processed once.

A stream also starts a pipeline: window 1m, sliding and session group its messages by time. This edition has a local broker, so tests send messages with .send.

stream.nexo
use nexo.stream

type Order:
    id: int
    total: int

fn process(o: Order):
    if o.total < 0:
        fail("negative total")
    print("order", o.id, o.total)

when kafka("orders") as msg, key: msg.json()["id"]:
    o: Order = validate(msg.json(), as: Order)?
    process(o)?

fn publish(row):
    print("per minute", row)

kafka("clicks")
  |> window 1m
  |> group by page
  |> count
  |> each publish

test "orders":
    kafka("orders").send({"id": 1, "total": 30})
    kafka("orders").send({"id": 1, "total": 30})
    kafka("orders").send({"id": 2, "total": -5})

test "clicks by minute":
    start = time(2026, 10, 24, 9, 0, zone: "UTC")
    kafka("clicks").send({"page": "/a"}, at: start)
    kafka("clicks").send({"page": "/b"}, at: start + 10s)
    kafka("clicks").send({"page": "/a"}, at: start + 20s)
    kafka("clicks").send({"page": "/a"}, at: start + 70s)

Feature flags in the code

A flags block declares each flag once: on or off, a percentage of users or the users that match a condition. flag(name, user) reads it.

A percentage is stable: the same user always gets the same answer, so a feature can grow from 10% to 100% without anyone seeing it come and go. nexo flags set changes a flag while the program runs, without a new release, and records who changed it.

flags.nexo
type User:
    id: int
    country: str

flags:
    new_checkout = 10%
    dark_mode = users where country == "ES"
    payments_v2 = off

ana = User(id: 7, country: "ES")
luis = User(id: 8, country: "FR")
print(flag("payments_v2"))
print(flag("dark_mode", ana), flag("dark_mode", luis))

var count = 0
for i in range(1, 1001):
    if flag("new_checkout", User(id: i, country: "ES")):
        count += 1
print("{count} of 1000 users see the new checkout")
print(flag("new_checkout", ana) == flag("new_checkout", ana))
$ nexo flags.nexo

true false

Personal data, kept by rule

Fields marked @personal or @private say what data is personal. @private fields are encrypted in the database and hidden by log, and keep erases old rows by itself. A personal type without keep and purpose is a warning, and an error in a release build.

privacy.export, erase and restrict answer a person's requests, and nexo privacy report lists what personal data the program holds, why, and who can read it.

Capabilities

From a script to a deployed service

The core stays small. Tools, the standard library and the cloud modules use the same syntax, so a program grows without changing language.

01Language

Readable by default

Indentation with a colon, no braces. Immutable unless you write var. Types are optional and inferred, and required only on pub functions.

Named and default arguments

Calls always use parentheses and can name their arguments, as in Account(owner: "Ana", balance: 100.00 EUR). Builders are just named arguments.

Comprehensions and lambdas

[x * x for x in range(1, 8) if x % 2 == 1] builds a list in one line, and lambdas work wherever a function does.

Tests built in

test blocks and assert live next to the code. assert ... fails checks that something fails. Run them with nexo test.

Contracts the compiler proves

When the compiler can prove an ensure, it costs nothing at run time. nexo build --release --trust-ensure also drops the checks it could not prove.

Two implementations, one output

The interpreter and the compiler run the same conformance suite and a differential test, and must print the same thing for every program.

02Tooling

One formatter, no options

nexo fmt makes all Nexo code look the same. It works on tokens and keeps your line breaks, so formatting never changes what a program does.

A linter with fixes

nexo lint warns about unused names, var that never changes, unreachable code and pipelines that never run, each with a fix. nexo fix applies the safe ones.

Your editor understands Nexo

nexo lsp gives any editor errors as you type, quick fixes, formatting, go to definition, hover and completion. The VS Code extension uses it.

03Library

A standard library for real programs

Dates, durations and time zones; find, regex and render templates; JSON and CSV with convert; an http client with retries; log, which hides @private fields.

Secrets that never leak

secret("NAME") can never be printed. password.hash, encrypt and sign are built in, and a key written in the code is a compile error.

Databases without SQL strings

With use nexo.db, @table types are the schema. Pipelines on tables become parameterised SQL on SQLite, with transactions, and nexo db diff and migrate keep the database in step.

Web servers in a block

A server block has typed routes, JWT auth, @role, @limit and secure headers. Errors become status codes, and nexo test serves the API on a free port.

AI as a function call

ask works with Anthropic, OpenAI and Ollama and checks typed answers. @tool functions and agent blocks call your code, and fake ask keeps tests offline.

C and Python when you need them

use c reads a C header and calls its functions. use python imports a Python module, so existing libraries stay within reach.

04Operations

Infrastructure in the same file

infra blocks declare apps, databases, storage, queues, networks and identities once, for AWS, Azure, GCP or Kubernetes. nexo plan shows the changes, the cost and the availability; apply, drift, destroy and import talk to each cloud's own API.

Pipelines that are ordinary code

The steps of a pipeline are Nexo code with run, test(), build_image, approve and apply. nexo ci run runs it on your machine and nexo ci export writes the GitHub, GitLab, Azure or Jenkins file.

Streams, flags and privacy

when kafka("orders") as msg handles messages with retries and dead letters, with window steps in pipelines. flags roll features out by percentage or audience, and @personal and @private fields are kept, encrypted and erased by rule.

Accounts guarded by expect, ensure and old(); a broken contract is an error that can be handled.

examples/bank.nexo
## Bank accounts with contracts: expect, ensure and old() guard every
## operation, and a broken contract is an error that can be handled.

type Account:
    owner: str
    balance: money

fn deposit(account: Account, amount: money):
    expect amount > 0.00 EUR
    ensure account.balance == old(account.balance) + amount

    account.balance += amount

fn transfer(source: Account, target: Account, amount: money):
    expect amount > 0.00 EUR
    expect source.balance >= amount
    ensure source.balance + target.balance == old(source.balance + target.balance)

    source.balance -= amount
    target.balance += amount

ana = Account(owner: "Ana", balance: 100.00 EUR)
luis = Account(owner: "Luis", balance: 20.00 EUR)

deposit(ana, 50.00 EUR)
transfer(ana, luis, 70.00 EUR)
print("{ana.owner}: {ana.balance}")

Records with methods, an enum, a trait and match with guards.

examples/grades.nexo
## Grade book: records with methods, an enum, match with guards and a trait.

trait Describable:
    fn describe(self) -> str

type Grade:
    Excellent
    Good
    Pass
    Fail

type Student is Describable:
    name: str
    scores: list[int]

    fn average(self) -> float:
        return self.scores.sum() / len(self.scores)

    fn describe(self) -> str:
        return "{self.name} ({len(self.scores)} exams)"

fn grade(avg: float) -> Grade:
    match avg:
        a if a >= 9: return Excellent
        a if a >= 7: return Good
        a if a >= 5: return Pass
        _: return Fail

fn label(g: Grade) -> str:
    match g:
        Excellent: return "excellent"
        Good: return "good"
        Pass: return "pass"
        Fail: return "fail"

students = [
    Student("Ana", [9, 10, 9]),
    Student("Luis", [6, 7, 5]),
    Student("Eva", [4, 3, 6]),
    Student("Marc", [8, 7, 9])
]

for s in students:
    avg = s.average()
    print("{s.describe()}: {round(avg, 1)} -> {label(grade(avg))}")

passed = students |> where grade(it.average()) != Fail |> count
print("Passed: {passed} of {len(students)}")

ranking = students |> sort by it.average() desc |> map name
print("Ranking: {ranking}")

test "grades follow the average":
    assert grade(9.5) == Excellent
    assert grade(7.0) == Good
    assert grade(4.9) == Fail

test "average of a student":
    assert Student("X", [5, 7]).average() == 6.0

The standard library in one program: a regex checks the email, only the Argon2id hash of the password is kept, the time is shown in another zone, a template is filled with render and signed, and log hides the @private field.

examples/signup.nexo
## Sign-ups: checks an email with a regular expression, stores only the
## hash of the password, signs the welcome letter and logs the account
## with its @private fields hidden. Shows the standard library.

type Account:
    name: str
    email: str
    password: str @private
    since: time

    keep = 5 years after since
    purpose = "logging in"

email_format = regex("^([a-z0-9.]+)@([a-z0-9]+)\\.([a-z]+)$")

fn sign_up(name: str, email: str, plain: str, moment: time) -> Account!:
    if not email_format.matches(email):
        fail("\"{email}\" is not a valid email")
    if len(plain) < 8:
        fail("the password needs at least 8 characters")
    return Account(name: name, email: email, password: password.hash(plain), since: moment)

fn log_in(account: Account, plain: str) -> bool:
    return password.check(plain, account.password)

opening = time(2026, 10, 26, 9, 30, zone: "Europe/Madrid")
attempts = [
    ["Ana", "ana@mail.com", "correct horse"],
    ["Luis", "luis(at)mail.com", "battery staple"],
    ["Eva", "eva@mail.com", "short"]
]

var accounts = []
for a in attempts:
    try:
        accounts.add(sign_up(a[0], a[1], a[2], opening))
        print("signed up: {a[0]}")
    else e:
        print("rejected {a[0]}: {e.message}")

ana = accounts[0]
print("Ana logs in: {log_in(ana, "correct horse")}, with a wrong password: {log_in(ana, "horse")}")
print("Ana in New York: {ana.since.to_zone("America/New_York")}")
print("parts of the email: {email_format.groups(ana.email)}")
log(ana)

letter = render("data/welcome.txt", name: ana.name, email: ana.email, since: ana.since.date)
print(letter, end: "")
pair = keypair.new()
signature = sign(letter, pair.private)
print("signed: {verify(letter, signature, pair.public)}, changed: {verify(letter + "!", signature, pair.public)}")

Get started

Run your first Nexo program

Nexo is not packaged yet, so you run it from a clone of the repository. The interpreter needs Python 3.12; the compiler also needs Rust (cargo) and clang.

  1. Install the interpreter

    Clone the repository and install it in a virtual environment.

    shell
    git clone https://github.com/marcrabadan/nexo.git
cd nexo
python3.12 -m venv .venv
.venv/bin/pip install -e '.[dev]'

  2. Write and run a program

    Save this as hello.nexo and run it, or start the REPL with .venv/bin/nexo.

    hello.nexo
    name = "world"
print("Hello, {name}!")
    $ nexo hello.nexo
    Hello, world!

  3. Try the everyday commands

    Run, test, format and lint from the same command.

    shell
    # run a program
.venv/bin/nexo examples/invoice.nexo
# run the test blocks
.venv/bin/nexo test examples/
# format, lint and apply the safe fixes
.venv/bin/nexo fmt app.nexo
.venv/bin/nexo lint app.nexo
.venv/bin/nexo fix app.nexo
# interactive REPL
.venv/bin/nexo

  4. Compile to native code

    The compiler generates LLVM IR and links it with a small runtime library that frees memory by reference counting and runs parallel on threads.

    shell
    cd compiler && cargo build --release && cd ..
compiler/target/release/nexo examples/invoice.nexo
compiler/target/release/nexo build --release app.nexo -o app
./app

Performance

How fast is Nexo?

The same programs in Nexo and six other languages, written the usual way in each and checked to print the same result. Over all of them, compiled Nexo sits behind C, Rust and Go and ahead of Java, JavaScript and Python. It is close to Rust on strings and integer loops, ahead of Go, Java, JavaScript and Python on strings and lists, close to Go and Rust on maps, and just behind Java and JavaScript on records, where every record is a heap object (the goals and where Nexo stands).

How it was measured

  • Measured on 2026-10-26, on Intel(R) Xeon(R) Processor @ 2.10GHz, 4 cores, Linux. Nexo: nexo build --release, LLVM IR built by Ubuntu clang version 18.1.3 (1ubuntu1); C: Ubuntu clang version 18.1.3 (1ubuntu1), -O2; Rust: rustc 1.97.0 (2d8144b78 2026-07-07), -O, overflow checks on; Go: go version go1.24.7 linux/amd64; Java: openjdk version "21.0.12.1" 2026-08-18; JavaScript: Node.js v22.22.0; Python: CPython 3.13.17.
  • Times include starting the program: hello shows that cost alone. It weighs most on Java and JavaScript, and these programs run for well under a second in the compiled languages.
  • Nexo and Rust check every integer operation for overflow; C, Go and Java wrap around silently, and Python's integers never overflow.
  • In C and Go a record is a plain value on the stack, so building one costs almost nothing; in Nexo, Java, JavaScript and Python each one is an object on the heap. That is most of the gap on records.
  • Each program uses its language's usual tools: ArrayList<Long> and HashMap in Java, a hand-written hash map in C, which has none. Python runs parallel on 4 processes, because its threads share one lock.
  • The Nexo interpreter is the prototype, a tree-walking evaluator written in Python; it shows the language works, not how fast it runs.
  • The programs and the script are in compiler/bench/: python3 compiler/bench/languages.py runs them again.
