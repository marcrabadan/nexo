Performance

Compare the recorded timings.

These measurements compare a fixed set of programs in Nexo and six other languages. Each program is checked to print the same result. The charts show time relative to the fastest implementation for each workload; the overall chart combines those ratios across the workloads, excluding the dedicated start-up workload. Results describe these programs on the machine below, rather than performance for every application.

How it was measured

  • Measured on 2026-10-26, on Intel(R) Xeon(R) Processor @ 2.10GHz, 4 cores, Linux. Nexo: nexo build --release, LLVM IR built by Ubuntu clang version 18.1.3 (1ubuntu1); C: Ubuntu clang version 18.1.3 (1ubuntu1), -O2; Rust: rustc 1.97.0 (2d8144b78 2026-07-07), -O, overflow checks on; Go: go version go1.24.7 linux/amd64; Java: openjdk version "21.0.12.1" 2026-08-18; JavaScript: Node.js v22.22.0; Python: CPython 3.13.17.
  • Times include starting the program: hello shows that cost alone. It weighs most on Java and JavaScript, and these programs run for well under a second in the compiled languages.
  • Nexo and Rust check integer operations for overflow. Go and Java use fixed-width integers with wrapping arithmetic; Python uses arbitrary-precision integers. C is compiled with -O2 without overflow checks.
  • In C and Go a record is a plain value on the stack, so building one costs almost nothing; in Nexo, Java, JavaScript and Python each one is an object on the heap. That is most of the gap on records.
  • Each program uses its language's usual tools: ArrayList<Long> and HashMap in Java, a hand-written hash map in C, which has none. Python runs parallel on 4 processes, because its threads share one lock.
  • Nexo interpreter timings are shown separately in the table. The charts and overall comparison use compiled Nexo.
  • The programs and the script are in compiler/bench/: python3 compiler/bench/languages.py runs them again.
