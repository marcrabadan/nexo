Reference

Language reference

Look up the syntax, types and rules of Nexo, with examples and their output. If you’re new to the language, start with the guided lessons.

Use the contents to find a topic, or explore working programs to see how the pieces fit together. The language specification defines the syntax and behavior in full.

Lexical structure

RuleWhat it means
EncodingUTF-8. Names may use Unicode letters, digits and _, and do not start with a digit.
BlocksA colon and 4 spaces of indentation per level. A tab is an error; there are no braces.
StatementsA newline ends a statement, except inside ( ), [ ] and { }, or when the next line starts with |>.
Comments# until the end of the line; ## is a documentation comment, shown by the editor on hover.
Numbers1_000, 3.14, 1e-3. A number with a unit is a unit literal: 30s, 5 km, 2 days, 10%, 19.99 EUR, 50GB.
Text"..." with {expr} interpolation, """...""" for several lines, and {{ for a literal brace.

Values and variables

A name is bound once with =; var makes it changeable. A type after the name is optional, and T? says the value may be missing (none); ?? gives a default for it.

values.nexo
name = "Ana"
var visits = 0
visits += 1
age: int = 30
email: str? = none

print("Hello {name}, you are {age}")
print(email ?? "no email")
print("{{name} is written {name}, and visits + 1 is {visits + 1}")

fruits = ["pear", "grape"]
prices = {"pear": 1.2, "grape": 3}
tags = set("new", "sale")
print(len(fruits), prices["pear"], "new" in tags)
$ nexo values.nexo
Hello Ana, you are 30
no email
{name} is written Ana, and visits + 1 is 2
2 1.2 true

Built-in types

TypeValues
int64-bit integer. Overflow is an Overflow error; it never wraps.
float64-bit floating point (IEEE 754).
decimalExact decimal, up to 28 significant digits.
moneyA decimal with an ISO 4217 currency: 49.90 EUR.
booltrue and false.
strText, with interpolation.
list[T][1, 2, 3]. A value: assigning it never shares its changes (copy on write).
map[K, V]{"pear": 1.2}. A value, like lists.
set[T]set("new", "sale"). A value, like lists.
T?A T or none.
T!A T or an error: the return type of a function that can fail.
weak T?A field that does not keep its record alive; it breaks a parent-child cycle.

Records are shared: two names can refer to the same record and see its changes. Durations (30s) and sizes (50GB) are unit literals with their own arithmetic.

Your own types

type is the only word for data you define: a record (fields, with methods inside), a union of values (type Status = "active" | "closed") or an enum whose variants may carry data. A trait lists the methods a type promises with is. Records are built with positional or named arguments.

types.nexo
type User:
    name: str
    age: int
    email: str? = none

    fn is_adult(self) -> bool:
        return self.age >= 18

type Status = "active" | "closed"

type Event:
    Click(x: int, y: int)
    Key(code: str)
    Quit

trait Shape:
    fn area(self) -> float

type Square is Shape:
    side: float

    fn area(self) -> float:
        return self.side ** 2

ana = User(name: "Ana", age: 30)
print(ana.is_adult(), ana.email ?? "-")
s: Status = "active"
print(s)
print(Square(2.0).area())

fn describe(e: Event) -> str:
    match e:
        Click(x, y) if x > 100: return "click on the right at {y}"
        Click(x, y): return "click at {x}, {y}"
        Key("q") or Quit: return "quit"
        _: return "a key"

for e in [Click(150, 4), Click(3, 4), Key("q"), Key("a"), Quit]:
    print(describe(e))

Control flow

if/elif/else, for x in ..., while, repeat n and pass for an empty block. A comprehension builds a list in one expression.

control.nexo
for i in 1..3:
    print(i)

repeat 2:
    print("again")

var n = 0
while n < 3:
    n += 1
print(n)

for word in ["a", "bb"]:
    if len(word) > 1:
        print("{word}: long")
    elif len(word) == 1:
        print("{word}: short")
    else:
        pass

print([x * x for x in range(1, 8) if x % 2 == 1])
$ nexo control.nexo

[1, 9, 25, 49]

match compares a value with patterns in order: _ matches anything, a literal matches itself, a variant takes its data apart (Click(x, y)), or joins patterns, and if adds a guard. See the describe function in Your own types.

Functions

fn defines a function; return is always explicit. Parameters can have defaults and every call can name its arguments. Types are optional, except on pub functions, which a module exports. A lambda (x -> x * 2) works wherever a function does.

functions.nexo
fn greet(person, greeting = "Hello"):
    return "{greeting}, {person}"

pub fn total(prices: list[float]) -> float:
    return prices.sum()

double = x -> x * 2

print(greet("Ana"))
print(greet("Luis", greeting: "Hi"))
print(total([1.5, 2.5]))
print(double(21))
print([1, 2, 3] |> map double(it))
$ nexo functions.nexo
Hello, Ana
Hi, Luis
4.0
42
[2, 4, 6]

Errors

An error is a value, never a hidden exception. A function that can fail returns T!, and there are only two things you can do with a possible error:

  • ? after the call passes it to the caller. It is only allowed inside a function that returns T!.
  • try with else e handles it on the spot; else e is NotFound handles one kind. e.message and e.kind describe it.

fail("...") makes an error of kind Error. A program that ends with an unhandled error shows it and exits with code 1.

errors.nexo
fn parse_age(text: str) -> int!:
    return validate(text, as: int, range: 0..150)?

try:
    print(parse_age("42"))
    print(parse_age("abc"))
else e:
    print("Invalid: {e.message} ({e.kind})")

try:
    print(read("missing.txt"))
else e is NotFound:
    print("not found")
else e:
    print("other error")

fn divide(a, b):
    if b == 0:
        fail("Cannot divide by zero")
    return a / b

try:
    divide(1, 0)
else e:
    print(e.message)
$ nexo errors.nexo
42
Invalid: "abc" is not a valid int (InvalidValue)
not found
Cannot divide by zero

Ignoring a call that can fail is found before the program runs:

ignored.nexo
fn load(path):
    return read(path)

load("notes.txt")
$ nexo ignored.nexo
Error in ignored.nexo, line 2:
  return read(path)
         ^^^^^^^^^^
The call to "read" can fail and its error is ignored. Add ? at the end to pass it to the caller, or handle it with try and else e.

Numbers and money

  • A number with a point is a float unless the variable, the parameter or the other operand is decimal or money.
  • Mixing float and decimal is an error; convert with decimal(x) or float(x). Adding money in two currencies is an error too; use convert(x, to: USD, rate: ...).
  • / gives a float between integers and a decimal between decimals; // is integer division.
  • round(x, digits) rounds half to even; mode: half_up changes it.
  • split(amount, parts) shares money without losing a cent: the first parts take the remainder.
numbers.nexo
print(0.1 + 0.2)
x: decimal = 0.1
print(x + 0.2)
print(7 / 2, 7 // 2, 7 % 2, 2 ** 10)

invoice: money = 120.00 EUR
print(invoice * 21%)
print(split(100.00 EUR, 3))
print(round(2.5), round(3.5), round(19.987, 2))
print(round(2.5, mode: half_up))

try:
    print(9223372036854775807 + 1)
else e is Overflow:
    print(e.kind)

Pipelines

|> passes a list, the rows of a CSV file or a table through steps. Columns of records and rows are used by name; it is the current element.

StepResult
where condThe elements for which cond holds
map exprEach element turned into expr
pick a, bOnly those columns
group by colGroups, which must be followed by sum, count or avg
sum col, count, avg colA total, a count, an average (per group after group by)
sort by expr [desc]Sorted, ascending unless desc
take nThe first n
each exprRuns expr for every element
save("file.csv")Writes the result as CSV or JSON, by the file's extension
  • Names. In a step, a bare name is first a column of the current row or a field of the current record, then a variable; it is the whole element.
  • Lazy. Nothing is read until the result is stored, passed, iterated or printed, or a final step (each, save, count, sum, avg) needs it; so read_lines(path) |> take 100 stops reading early.
  • Functions. Any function is a step: xs |> f is f(xs). In map and each, a step that is a function is called with the element: each print, map double.
  • Groups. After group by region each row has the key column region and the aggregate column named after its argument (sum amount gives amount, count gives count).
  • Empty. sum of nothing is 0 and avg of nothing is none; avg of ints is a float.
  • Everywhere. The same steps run on lists, CSV tables, the lines of a file, database tables (as SQL) and streams (with time windows), and the compiler fuses where, map and sum into one loop.
pipes.nexo
type Sale:
    region: str
    product: str
    amount: float

sales = [
    Sale("north", "laptop", 1200.0),
    Sale("south", "mouse", 25.0),
    Sale("north", "mouse", 30.0),
    Sale("east", "laptop", 1100.0),
    Sale("south", "laptop", -50.0)
]

sales
  |> where amount > 0
  |> group by region
  |> sum amount
  |> sort by amount desc
  |> each print("{it["region"]}: {it["amount"]}")

print(sales |> where product == "laptop" |> count)
print(sales |> map amount |> avg)
print(sales |> sort by amount |> take 2 |> map product)
print(sales |> pick region, amount |> take 1)
print([3, -1, 2] |> where it > 0 |> map it * 10)
$ nexo pipes.nexo

east: 1100.0
south: 25.0

Contracts and tests

expect states what must hold when a function starts, ensure what must hold when it returns, and old(expr) is a value as it was on entry. A broken contract is a ContractBroken error with the values involved. The compiler leaves out the ensure checks it can prove.

test "name": blocks live next to the code and run with nexo test; running the file skips them. assert expr checks a condition, and assert expr fails checks that it fails.

contracts.nexo
type Account:
    owner: str
    balance: money

fn deposit(account: Account, amount: money):
    expect amount > 0.00 EUR
    ensure account.balance == old(account.balance) + amount
    account.balance += amount

ana = Account(owner: "Ana", balance: 10.00 EUR)
deposit(ana, 5.00 EUR)
print(ana.balance)
try:
    deposit(ana, -1.00 EUR)
else e is ContractBroken:
    print(e.message)

test "a deposit adds to the balance":
    a = Account(owner: "A", balance: 0.00 EUR)
    deposit(a, 2.00 EUR)
    assert a.balance == 2.00 EUR

test "a negative deposit fails":
    assert deposit(Account(owner: "B", balance: 0.00 EUR), -1.00 EUR) fails
$ nexo contracts.nexo
15.00 EUR
expect amount > 0.00 EUR does not hold (amount = -1.00 EUR)
$ nexo test contracts.nexo
15.00 EUR
expect amount > 0.00 EUR does not hold (amount = -1.00 EUR)
✓ a deposit adds to the balance
✓ a negative deposit fails
2 tests: 2 passed, 0 failed

nexo test --coverage runs the same tests and then says how many branches they ran, and which never ran: the body of each function, each branch of an if (and the case where no condition holds), each arm of a match, each loop body and each else of a try. Code inside test blocks and lambdas is not counted.

coverage.nexo
fn label(n: int) -> str:
    if n == 0:
        return "none"
    elif n < 10:
        return "few"
    return "many"

fn total(xs: list) -> int:
    var t = 0
    for x in xs:
        t += x
    return t

test "labels":
    assert label(0) == "none"
    assert label(50) == "many"
    assert total([]) == 0
$ nexo test --coverage coverage.nexo
✓ labels
1 test: 1 passed, 0 failed
Branch coverage: 4 of 6 (66%).
coverage.nexo:5: the elif branch never ran.
coverage.nexo:11: the loop body never ran.
Add tests that run them; nexo test --suggest proposes some.

Modules: code from other files

A program can be split into several .nexo files. Each file is a module, and another file uses it with use. There is nothing to install or register: the file is the module.

The name of a module is its path

  • use shop.payments loads the file shop/payments.nexo: each dot is a folder, and the last name is the file without .nexo.
  • Paths start at the root of the project: the folder of the nearest nexo.toml above the program (nexo new writes one), or the program's own folder when there is none. So a module has the same name in every file that uses it, wherever that file is.
  • Names that start with nexo. are official modules (use nexo.db, use nexo.sync), not files.
  • use goes at the top level of a file, usually at its start.

A project with two modules and a program that uses them:

the project
project/
  nexo.toml
  app.nexo
  shop/
    prices.nexo
    payments.nexo
shop/prices.nexo
## The price with 21% VAT, in cents.
pub fn with_vat(cents: int) -> int:
    return cents + cents * VAT // 100

VAT = 21

print("prices loaded")
shop/payments.nexo
use shop.prices

pub type Status:
    Paid(cents: int)
    Pending

pub fn charge(cents: int) -> Status:
    if cents == 0:
        return Pending
    return Paid(prices.with_vat(cents))

fn audit():
    print("only visible inside this module")

test "charge adds VAT":
    assert charge(100) == Paid(121)

Using what a module exports

  • Only what is marked pub leaves the file: pub fn, pub type, and the variants of a pub enum. Constants, vars, traits and functions without pub stay inside it; to share a value, export a pub fn that returns it.
  • Exported names are always written with the module's last name in front: payments.charge(100), payments.Status, and payments.Paid(n) in a match. There is no import of bare names, so the reader always sees where a name comes from.
  • use shop.prices as p gives the module another name in this file: p.with_vat(1000). Use it when two modules end with the same name, or a name is long.
app.nexo
use shop.payments
use shop.prices as p

print(p.with_vat(1000))

match payments.charge(100):
    payments.Paid(n): print("paid {n}")
    payments.Pending: print("nothing to pay")
$ nexo app.nexo
prices loaded
1210
paid 121

prices loaded appears once although both app.nexo and payments.nexo use shop.prices: a module's top-level code runs once, at its first use, in its own scope, which only sees the builtins and the modules it uses itself.

Tests and tools

  • The test blocks of a module run only when it is the file given to nexo test: nexo test shop/payments.nexo runs charge adds VAT, and nexo test app.nexo does not. nexo test with no file runs every file of the folder, so every module's tests.
  • nexo check, nexo lint, the editor (nexo lsp) and nexo docs read the modules too; an error inside a module shows the module's file and line.

Mistakes are found before the program runs

A missing file, a name the module does not have or does not export, two modules that use each other (the cycle is shown), and using a module's name as a value are compile errors, with the fix:

private.nexo
use shop.payments

payments.audit()
$ nexo private.nexo
Error in private.nexo, line 3:
  payments.audit()
  ^^^^^^^^^^^^^^
"audit" is not pub in module shop.payments. Write pub before its fn or type in shop/payments.nexo; a module only exports its pub functions and types.
typo.nexo
use shop.payment
$ nexo typo.nexo
Error in typo.nexo, line 1:
  use shop.payment
  ^^^^^^^^^^^^^^^^
There is no module shop.payment: there is no file shop/payment.nexo. Create the file or fix the name; a module's name is its path (shop/payments.nexo is shop.payments).

Concurrency

parallel for runs its body as tasks on threads, and the results and any output come back in the order of the list; a parallel: block runs its statements at the same time. A task may only change what it created itself. use nexo.sync adds spawn, typed channels, select and shared variables; when every task waits, Nexo reports a deadlock instead of hanging.

parallel.nexo
use nexo.sync

sizes = parallel for word in ["one", "three", "seven"]:
    return len(word)
print(sizes)

fn produce(out: channel[int], n: int):
    for i in 1..n:
        out.send(i)
    out.close()

numbers = channel[int](size: 2)
spawn produce(numbers, 4)
var total = 0
for x in numbers:
    total += x
print(total)
$ nexo parallel.nexo
[3, 5, 5]
10

Patterns

Five design patterns have their own word; the rest are written with functions, match and named arguments (section 10).

  • single name: holds one value with the fields written in it, at the top level of a file; config.port = 9090 changes it everywhere.
  • states name: lists the transitions as chains, new -> paid -> shipped; it starts in the first state. .state is the current one, .can("x") says whether it may go there, and .go("x") goes or fails with InvalidValue.
  • protect(value, fails: 5, wait: 1m): is a circuit breaker: after fails errors in a row its block is not run for wait, and it fails with CircuitOpen instead.
patterns.nexo
single config:
    port = 8080
    mode = "production"

config.port = 9090
print(config)

states order:
    new -> paid -> shipped -> delivered
    new -> cancelled
    paid -> cancelled

order.go("paid")
print(order.state, order.can("delivered"))
try:
    order.go("delivered")
else e is InvalidValue:
    print(e.message)

fn charge(amount: int) -> int!:
    if amount < 0:
        fail("card declined")
    return amount

fn pay(amount: int) -> int!:
    var paid = 0
    protect(charge, fails: 2, wait: 1m):
        paid = charge(amount)?
    return paid

for amount in [-1, -2, 5]:
    try:
        print(pay(amount))
    else e is CircuitOpen:
        print(e.message)
    else e:
        print(e.message)
$ nexo patterns.nexo
config(port: 9090, mode: "production")
paid false
"order" cannot go from "paid" to "delivered"; from "paid" it can go to "shipped", "cancelled"
card declined
card declined
"charge" is not called for 1m: it failed 2 times in a row

action name(params): is a command that can be undone: do: says what it does and undo: how to reverse it, each on its line or as a block. Calling it runs do and remembers its arguments; undo() reverses the last action not yet undone and gives true, or false when there is none. The calls inside need no ?: an error in do or undo is the error of the call, and an action that failed is not remembered. Actions go at the top level of a file.

actions.nexo
var lines = ["first"]

action add(line: str):
    do: lines = lines + [line]
    undo: lines = [l for l in lines if l != line]

add("second")
add("third")
print(lines)
undo()
print(lines)
print(undo(), undo())
print(lines)
$ nexo actions.nexo
["first", "second", "third"]
["first", "second"]
true false
["first"]

workflow name(params): is a list of steps that runs like a function. A step may have an undo on the next line, indented. step wait condition, max: 3 days checks the condition every second until it is true, and fails with Timeout after max. When a step fails, the undo of every step already done runs, last first, and the call fails with the step's error. The state is saved in .nexo/workflows/ after every step: a program that stops half way runs the same workflow with the same arguments from the step it stopped in, the next time it is called.

workflows.nexo
var accounts = []

fn create_account(email: str):
    accounts = accounts + [email]

fn delete_account(email: str):
    accounts = [a for a in accounts if a != email]

fn confirmed(email: str) -> bool:
    return email in accounts

fn send_welcome(email: str):
    if email.ends_with(".invalid"):
        fail("no mailbox for {email}")
    print("welcome,", email)

workflow customer_signup(email: str):
    step create_account(email)
        undo delete_account(email)
    step wait confirmed(email), max: 3 days
    step send_welcome(email)

customer_signup("ana@example.com")
try:
    customer_signup("bob@example.invalid")
else e:
    print(e.message)
print(accounts)
$ nexo workflows.nexo
welcome, ana@example.com
no mailbox for bob@example.invalid
["ana@example.com"]

Standard library

Always available, without use. A function that can fail returns T!, so it is called with ? inside a function that can fail, or inside try. Every access to files, the network, the environment, commands, C or Python first asks the program's policy. nexo docs --for-ai prints this list, from nexo/stdlib/api.json, the same file both implementations use.

AreaNames

Files and data

CallWhat it does
print(values..., end: "\n")Writes the values separated by spaces, then end. Text inside a list or map is shown with quotes.
input(prompt?) -> strShows the prompt and reads one line, without its newline; "" at the end of the input.
read(path) -> str!The text of a file; a .csv file is read as a table: a list of rows, each a map from column to value. Fails with NotFound or IOError.
write(path, text) -> none!Writes (or replaces) a file; its folder must exist (NotFound otherwise).
read_lines(path) -> list!The lines of a file, read as they are used: read_lines("50GB.log") |> take 100 reads 100 lines.
save(value, path) -> none!The last step of a pipeline: CSV for .csv, JSON for .json, one line per element otherwise. Money is written as text ("19.99 EUR") and decimals keep every digit.
move_file(path, to: folder) -> str!Moves a file into a folder, creating it, and returns the new path: move_file("a.txt", to: "old") gives "old/a.txt". It does not rename.
json.parse(text, as: T?) -> T!Reads JSON. With as: it builds records, applies defaults and reports a missing field or a wrong type as InvalidData.
csv.parse(text) -> list!A list of maps. A column of integers is int, of numbers float, otherwise text; an empty cell is none.
convert(data, to: json|csv) -> strData as JSON (indented by two spaces) or CSV text.
files.nexo
type Sale:
    region: str
    amount: float

try:
    write("sales.csv", "region,amount\nnorth,120.5\nsouth,80\nnorth,30\n")
    rows = read("sales.csv")  # a .csv file is read as a table
    print(rows[0], rows[0]["amount"])
    for line in read_lines("sales.csv") |> take 2:
        print(line)
    rows |> group by region |> sum amount |> save("totals.json")
    print(read("totals.json"))
    sale = json.parse("{{\"region\": \"east\", \"amount\": 9.5}", as: Sale)
    print(sale, sale.amount)

  • date(y, m, d) is a day: .year, .month, .day, .weekday (1 is Monday). It moves by whole days, months or years, and two dates subtract to days.

Network and tests

http.get(url, headers:, timeout:, retries:), http.post(url, body, ...), put, patch and delete return a response with .status, .text, .headers and .json(). A map or record body is sent as JSON. A status of 400 or more is an HTTPError, and a connection that fails a NetworkError; get, put and delete retry twice after a network error or a 502, 503 or 504; post and patch never retry, since repeating them may repeat their effect. The timeout is 30s by default. Inside a test, fake f returns value replaces a function, a library one or ask, until the test ends. The example starts a nexo.web server and calls it:

        return items[n]

        return item

nexo.db: databases

  • db = connect("shop.db", key: secret(...)?) opens or creates an SQLite file; connect("postgres://user@host/shop", key: secret("DB_PASS")) opens a PostgreSQL server and connect("mysql://user@host/shop", ...) a MySQL one (TLS for any host but this machine), with the same tables, queries and migrations. connect("mongodb://user@host/shop", ...) and connect("elasticsearch://user@host:9200/shop", ...) keep the same tables in MongoDB and Elasticsearch, with the same queries and results; there db.sql is an error, there is no schema to migrate, and db.transaction undoes its writes when it fails but does not hide them from other programs before it ends. Each @table type is a table: id: id is the automatic key, @unique a unique column, ref T a foreign key and many T the rows that point back.
  • db.T.add(field: value...) inserts and returns the record; db.T.find(field: value) -> T! fails with NotFound; db.T.update(record, field: value), db.T.remove(id), db.T.all() and db.T.count().
  • A pipeline on db.T becomes one parameterised SQL query: where comparing columns with values (also through a ref: where customer.city == "Rome"), sort by, take, count, pick of columns and group by followed by count, sum or avg run in the database, and the rows of ref fields are read with one query per field; from the first step that cannot be translated, the rest runs in memory with the same result. NEXO_SQL_LOG=1 shows the SQL.
  • db.transaction: keeps or undoes everything inside together; a failure in it is a DatabaseError.
  • db.sql("... {value}") runs raw SQL written in the call; the values in braces are always parameters, so a query built from text is an error.
  • nexo db diff file.nexo compares the types with the database and writes a migration; nexo db migrate applies it in a transaction, and dropping a column needs --allow-drop.

nexo.sync: workers and channels

  • spawn f(args) starts a task that runs on its own; it is not waited for.
  • channel[T](size: n) is a typed queue: send waits while it is full, receive while it is empty, and for x in c reads until close(). A record sent through a channel is copied, so each task owns what it gets.
  • select: waits on several channels with name from channel: lines and an optional after 5s:.
  • shared x = ... is the only state tasks may change together; the locks are added by the compiler. When every task waits, Nexo reports a deadlock instead of hanging.
sync.nexo
use nexo.sync

fn producer(c: channel[int], n: int):
    for i in 1..n:
        c.send(i)
    c.close()

fn worker(c: channel[int], done: channel[int]):
    var total = 0
    for n in c:
        total += n * n
    done.send(total)

queue = channel[int](size: 10)
done = channel[int](size: 4)
spawn producer(queue, 100)
repeat 4:
    spawn worker(queue, done)
var total = 0
repeat 4:
    total += done.receive()
print("sum of squares:", total)

alerts = channel(size: 1)
alerts.send("disk full")
select:
    a from alerts: print("alert", a)
    after 1s: print("quiet")

shared seen = {}
fn remember(k, v):
    seen[k] = v
parallel for n in 1..10:
    remember(n, n * 2)
print(len(seen), seen[7])

nexo.web: servers

  • server name: with port = n and routes get|post|put|patch|delete "/path/{param}"(param: type, ...):. Path, query and JSON body parameters are checked against their types; a wrong one answers 400.
  • What a route returns is the answer: a status code (return 404), none (204), a text (text/plain) or any other value as JSON, with 201 for post and 200 otherwise. An error that leaves the route answers too: NotFound is 404, InvalidValue and InvalidData 400, a repeated @unique 409, anything else 500.
  • auth = jwt(key: ...) protects every route; @public opens one, @role("admin") asks for a role, @limit(10 per minute per ip) limits the calls. tokens.sign(claims, expires: 1h) makes a token.
  • Secure headers are always sent, and a POST, PUT, PATCH or DELETE from another origin answers 403. Under nexo test the server answers on a free port, and name.url is its address. The example is in Network and tests.

nexo.stream: real-time data

A stream is one more source for when and |>. when kafka("orders") as msg: handles one message at a time: a message that fails is tried 4 times and then goes to orders.dead, and key: makes a repeated key run once. |> window 1m, sliding 5m and session 30s group messages by time for the usual steps. kafka("t").send(value, key: k?, at: time?) publishes. Without a broker a stream is on a local one, with partitions: n handled in parallel, each in order; servers: (Kafka), url: (RabbitMQ), namespace: (Event Hubs, Service Bus), region: (SQS, Kinesis) and project: (Pub/Sub) put it on its broker or cloud, with key: secret(...) as the broker's password, and websocket("wss://host/path") reads a WebSocket server. nexo test runs every stream on an in-memory broker.

Fields marked @personal or @private are personal data: @private ones are encrypted in the database with the key: of connect and hidden by log. keep = 2 years after field erases old rows by itself and purpose says why the data is kept. privacy.export(record) writes its data to table-id.json, privacy.erase(record) deletes or anonymises it, and privacy.restrict(record) keeps it out of every query.

use nexo.db

db = connect("crm.db")

@table
type Contact:
    id: id
    name: str @personal
    phone: str @personal
    last_call: date

    keep = 2 years after last_call
    purpose = "support calls"

ana = db.Contact.add(name: "Ana", phone: "600 000 000", last_call: date(2026, 9, 1))
luis = db.Contact.add(name: "Luis", phone: "600 111 111", last_call: date(2026, 9, 2))
privacy.export(ana)
print(read("contact-1.json"))
privacy.erase(ana)      # deletes the row: its personal data is gone
privacy.restrict(luis)  # keeps the row, but the program stops reading it
print(db.Contact.count())
print(len(db.sql("SELECT id FROM contact")))  # db.sql still reads it, for legal duties

nexo.infra and nexo.ci: deployment

  • infra name: with cloud = "aws"|"azure"|"gcp"|"k8s" declares portable resources (app, database, storage, queue, network...) and native ones of a cloud. stage prod: changes values per stage, and state = s3("bucket") keeps the state outside .nexo/state.
  • nexo plan asks the cloud's own API what exists and shows the changes, the cost and the availability; apply, destroy, drift, cost and import use the same API.
  • pipeline name: has steps that call run(command), test(), build_image(name), plan(...), apply(...), approve(by: [...]) and comment(text). nexo ci run runs it here, and nexo ci export github|gitlab|azure|jenkins writes the file of that service. A pipeline that runs commands needs allow shell.
deploy.nexo
policy:
    allow shell

infra shop:
    cloud = "gcp"
    region = "europe-west1"
    budget = 100 EUR per month
    storage photos
    database orders
    app api:
        image = "shop:1.0"
        port = 8080
        replicas = 1..4
        env:
            DB = orders.url
            API_KEY = secret("API_KEY")
    output url = api.url

stage prod:
    size = large
    replicas = 2..8

pipeline release:
    trigger push to main
    version = "1.4.0"

    step build:
        test()
        image = build_image("shop-api")

    step review:
        comment(plan(stage: "prod", image: image))
        approve(by: ["ops@shop.example"])

    step prod:
        apply(stage: "prod", image: image)

    after failure:
        run("echo the release failed")

use c and use python

use c "libm" reads the library's C header when the program is compiled, so every call is checked against the real signature; use c "./lib.so" as name loads a file. use python module as name imports a Python module; numbers, text, lists and maps cross both ways. Calls into C are the only unsafe code in this edition, and nexo audit lists every one.

The program policy

Nexo Shield adds strict execution, synchronous dependency ceilings and hardened Docker deployment with an explicit offline Linux worker. See its architecture and security boundaries.

A policy: block lists, with allow and deny, what the program may read, write, reach on the net, take from the environment, run as a shell command, and load with c and python. Every access of the library asks it first, following links and ... A release build stops at anything not allowed; development mode warns once, except shell commands, which always need allow shell. nexo policy show prints what a program may do and nexo policy suggest learns the smallest policy from its tests.

report.nexo
policy:
    allow read "sales.csv"
    allow write "report.txt"
    deny read "secrets/"

rows = read("sales.csv")
write("report.txt", "{len(rows)} rows")
print(read("report.txt"))
print(read("secrets/keys.txt"))

Command line

Both implementations take the same commands: .venv/bin/nexo (the interpreter) and compiler/target/release/nexo (the compiler).

Set up native compilation

The interpreter runs your source file directly. The compiler turns it into machine code for your computer. You write the same Nexo syntax with either one.

After installing Rust (including Cargo) and clang, run these commands from your Nexo checkout. Save hello.nexo using the first-program instructions. The last command compiles and runs it.

From the Nexo folder
cd compiler
cargo build --release
cd ..
compiler/target/release/nexo hello.nexo

See the compiler setup guide for requirements and build details, or explore the benchmark programs and measurements.
