For AI agents

The compiler, as tools for your agent.

nexo mcp exposes check, test, API lookup, infrastructure plan and format over the Model Context Protocol. Diagnostics carry their fix, the API surface is enumerable and formatting is canonical, so an agent can run the edit, check, fix loop without guessing.

Configure the server

The server speaks JSON-RPC 2.0 on stdio, one message per line, protocol version 2025-06-18. Start it from the project root: every tool path is resolved against that folder.

MCP client configuration
{
  "mcpServers": {
    "nexo": { "command": "nexo", "args": ["mcp"] }
  }
}

Use an absolute path to the executable if it is not on PATH, such as /path/to/nexo/.venv/bin/nexo.

Tools and protocol

ToolRuns
check(path?)nexo check: compile without running; every error with its fix
run_tests(path?)nexo test: the test blocks, one result each
docs_for_ai(path?)nexo docs --for-ai: the exact API surface and the file’s declarations
plan(path?, stage?)nexo plan: what apply would change, without applying it
format(path)nexo fmt: the one layout, same tokens
  • Each call runs the same nexo as a subprocess with no stdin and a 600 s timeout; the result is its combined output, with isError set from the exit code.
  • Paths must be relative and stay inside the project: absolute paths and escapes through .. or symlinks are refused before anything runs. Unknown or non-string arguments are rejected against each tool’s inputSchema (additionalProperties: false).
  • apply, destroy, deployments and secrets are never exposed: infrastructure changes require a person.

The agent loop

  1. Ground. nexo docs --for-ai prints every callable from nexo/stdlib/api.json, which a test keeps identical to the builtins of both runtimes. Any other name must be defined by the program; an undefined one is reported with its location and a “Did you mean…?” suggestion.
  2. Check. nexo check --json emits schema-versioned diagnostics (diagnostics-v1): LSP-shaped ranges in UTF-16, a stable code such as ignored_error, and data.fixes with text edits and a safe flag.
  3. Repair. nexo fix applies the fixes marked safe. nexo fmt has no options and preserves tokens, so two agents editing the same file converge on the same text.
  4. Test. nexo test --suggest derives edge cases from types, contracts and unions; nexo test --coverage reports branch coverage, identically in both runtimes.
  5. Verify intent. nexo check --intent asks the configured model whether each function matches its ## comments and expect/ensure contracts.

Generated code still runs under the program’s policy: accesses to files, hosts, environment variables, shell, C or Python that it does not allow are refused by the standard library. For kernel-level confinement use a Nexo Shield profile.

Context for assistants without MCP

The prompt generator builds a Nexo prompt per profile in two sizes: Compact, which points the model at llms.txt and retrieves topics on demand, and a self-contained version for assistants that cannot fetch URLs. Each prompt is versioned by a hash of its sources, and its token count is measured with tiktoken 0.12.0 (cl100k_base); a test rejects counts that no longer match the text.

Counts cover the prompt only, not your task, history, retrieved documents or the response, and tokenizers differ between providers. The generator runs locally; pasting a prompt into an external assistant sends it to that provider.

Building agents in Nexo

nexo.ai provides ask, streaming, @tool functions and agent blocks with max_steps, confirm for tools that need a person, and mcp("name") tool sources. Tools obey the program policy. max_tokens bounds reported input plus output tokens across an invocation; money budgets per day and output limits are separate controls. Usage checks rely on the provider’s reported usage and are not a guaranteed invoice ceiling. nexo.ai guide · Token budgets
