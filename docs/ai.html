Connect your assistant with MCP

nexo mcp runs a Model Context Protocol server on stdio. It offers check, run_tests, docs_for_ai, plan and format by running the same commands you use. It never offers apply: changes to infrastructure always wait for a person.

MCP client configuration
{
  "mcpServers": {
    "nexo": { "command": "nexo", "args": ["mcp"] }
  }
}

Use the full path of the nexo executable if it isn’t on your PATH, such as .venv/bin/nexo inside the cloned repository.

The loop your agent can close

  1. Ground. nexo docs --for-ai prints the exact functions a program can use, so the model doesn’t invent APIs.
  2. Check. nexo check --json returns structured diagnostics; every message that reports a problem says how to fix it.
  3. Repair. nexo fix applies the safe fixes and nexo fmt keeps one canonical layout, so diffs stay small.
  4. Prove. nexo test --suggest proposes edge cases from types and contracts; nexo test --coverage shows the branches that ran.

Code the agent writes runs inside the program’s policy: files, hosts, environment variables and commands it didn’t declare are refused. See Nexo Shield for stronger isolation.

Start with one focused task

  1. Choose Compact context. Select a profile and whether your assistant can open documentation URLs. Use the self-contained option when it cannot.
  2. Add your task. Include the relevant source, the change you want and how you will check the result.
  3. Ask for a focused result. Request a patch or a short explanation, then run the Nexo checks. Add context when a specific gap appears.

The prompt generator runs in your browser without an account or API key. Copying the prompt into an external assistant sends it to that provider under its own terms.

Control input and output separately

Compact prompts and selective documentation retrieval reduce the context you send. A focused response request can keep output shorter. The prompt generator includes measured prompt counts and a local token and cost comparison tool.

Those counts cover prompt text, not your task, chat history, retrieved documents or the model’s response. Tokenization varies by provider. Shorter prompts do not guarantee better answers or lower total cost if they cause more correction rounds.

Building an agent in Nexo?

The AI Guide helps a coding assistant work with Nexo. To build your own model-powered application, use the AI library guide. Agents support invocation token allowances; monetary reservations and model output limits are separate controls. Reported usage checks are not a guaranteed provider-invoice ceiling.

For larger projects, the full prompt tool also includes optional project planning, architecture and readiness forms. Use them when they help the task.
