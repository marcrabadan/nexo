RFC-0001 · Experimental M1–M2

Nexo Web

Readable Nexo components compiled to JavaScript, HTML and scoped CSS. Local state updates the DOM directly, with no virtual DOM or React dependency.

Try two Counters · Try M2 composition and routing · Language and lifecycle reference

M1 and M2 run through the Python CLI. The Rust driver does not compile browser components. The existing WASI command nexo build --target web keeps its established behavior.

One readable component

A component combines local state, an action written with fn, a view and a style. This is the exact acceptance example compiled into the demo.

counter.nexo · M1
use nexo.web

pub component Counter:
    state count: int = 0

    fn increment():
        count += 1

    view:
        main:
            h1("Nexo Web")
            p("Count: {count}")
            button("+", on_click: increment)

    style:
        main {
            padding: 24px;
        }

Every instance gets fresh typed state. Clicking the native button batches state changes and updates only bindings that depend on them, skipping unchanged rendered values. Text becomes text nodes, so markup in strings is displayed safely. Destroying a mount removes its listeners and subscriptions.

Actions currently support local assignments; state types are int, str and bool. Expressions include literals, state reads, interpolation, checked integer arithmetic and string concatenation. Unsupported syntax and reserved words used as state/action names produce a diagnostic.

From readable source to the browser

  1. Nexo Web source

    Components, state, views and styles.
    Pages, layouts and owner-scoped context: experimental M2.

  2. Nexo compiler

    Parse → typed component AST → binding dependencies → DOM instructions + scoped CSS.

    Static bindings have no subscription. Static markup extraction is future optimization.

  3. Browser

    External JavaScript + HTML + CSS. Direct DOM updates; independent owners and cleanup.

React offers component composition; Solid demonstrates fine-grained updates; Svelte moves work into compilation; Vite supplies development tooling. Nexo Web pursues those useful properties with native Nexo syntax. Nexo Web remains much smaller: composition is implemented in experimental M2; Vite/HMR remain planned. No comparative performance claim has been measured.

Compose screens with M2

Components take typed, read-only scalar properties. Project imports use qualified use names and pub exports. A component projects nested content through slot(); a layout owns persistent shared structure. Each provider creates its own context instance; inject() resolves the nearest provider.

Pages declare explicit paths and typed parameters. M2 uses fragment URLs such as #/users/7, so the working demo runs on static hosting. Local anchors, back/forward navigation, nested layout persistence, page metadata, not-found and navigation error pages are supported. Navigation focuses the new page content.

Run the complete project · Download the entry · All project files. This entry requires its session.nexo, ui/widgets.nexo, ui/card.css and nexo.toml files; it is not a standalone snippet.

composition/app.nexo · M2
use nexo.web
use session
use ui.widgets

pub layout Shell:
    provide session.Visits
    visits = inject(session.Visits)
    state opens: int = 0

    fn open():
        opens += 1

    view:
        header:
            h1("Nexo Web M2")
            p("Shared visits: {visits.count}; layout clicks: {opens}")
            button("Layout +", on_click: open)
            nav:
                a("Home", href: "/")
                a("User 7", href: "/users/7")
        slot()

pub layout Details:
    layout = Shell
    state opens: int = 0

    fn open():
        opens += 1

    view:
        section:
            h2("Persistent nested layout")
            p("Nested layout clicks: {opens}")
            button("Nested +", on_click: open)
            slot()

pub page Home:
    path = "/"
    layout = Shell
    title = "Nexo Web — Home"
    description = "A compiled Nexo component, layout and context example."
    visits = inject(session.Visits)
    state label: str = "Local count"

    fn rename():
        label = "Updated count"

    view:
        main:
            widgets.Card(heading: label):
                p("Shared in slot: {visits.count}")
                button("Shared +", on_click: visits.increment)
                button("Rename", on_click: rename)
                widgets.Counter(label: label)

pub page User(id: int):
    path = "/users/{id}"
    layout = Details
    title = "Nexo Web — User {id}"
    visits = inject(session.Visits)

    view:
        main:
            h2("User {id}")
            p("Shared on another page: {visits.count}")
            button("Shared +", on_click: visits.increment)

pub page NotFound:
    not_found = true
    layout = Shell
    title = "Nexo Web — Not found"

    view:
        main:
            h2("Page not found")
            a("Return home", href: "/")

pub page Failure:
    error = true
    title = "Nexo Web — Error"

    view:
        main:
            h2("Unable to render this page")

Shared layout state survives navigation through a common layout prefix. Page state resets when leaving a page or changing parameters. Context updates batch across owners. Slots retain caller bindings and CSS, while their listeners and subscriptions are cleaned up with the receiving component.

Props and route parameters support int, str and bool. Layouts require exactly one slot and have no props yet. Local project modules/CSS are supported; package imports, conditional/keyed-list rendering, browser APIs and SSR remain future work. Error pages handle mount/navigation failures, not arbitrary event exceptions.

Scoped CSS

Write standard CSS selectors and declarations. The compiler emits an external stylesheet with native @scope boundaries. Custom properties and media/container/supports queries work. Use a modern browser with CSS scope support.

Local @import "./card.css"; is expanded into the component scope in M2. Remote imports and resource functions such as url() and image-set(), global at-rules, CSS escapes and minification remain unsupported. Styles are component-owned; no inline style is needed.

Install Nexo from the repository first. Build emits index.html, main.js, app.js and app.css. Serve over HTTP; file URLs cannot reliably load ES modules. web new/dev/preview/audit, --release, source maps and frontend LSP support are not available.

Diagnostics: NW1001 grammar, NW1002 names/types, NW1003 CSS boundaries, NW1004 unsafe DOM, NW1000 I/O. M2 adds NW2001 modules, NW2002 props/composition, NW2003 routes, NW2004 context and NW2005 slots. Each compile error gives a fix. Inspect JSON diagnostics before changing code.

Pages represent routable screens; layouts own persistent shared structure and a slot; context belongs to the provider subtree. Future typed API reads will use load and explicit writes will use mutation; those M3 APIs are not available.

Security and accessibility

Browser compilation rejects server imports, arbitrary calls, HTML injection, script elements, URL attributes and inline event code. Generated demo assets use a restrictive CSP. Never put secrets in a browser bundle. Visibility checks never replace server authorization.

Shield remains a backend security foundation: use supported policy, authentication, authorization, rate-limit and CSRF controls. Its bounded loopback ingress is not a persistent production web server. Production needs HTTPS, secure HttpOnly sessions and a separately validated backend. OWASP ASVS 5.0 guides future reviews; M1 is not a certification.

Native elements support keyboard interaction. Authors remain responsible for meaningful labels, focus, headings, contrast and ARIA. The compiler does not yet perform an accessibility audit.
