RFC-0001 · Experimental M1–M5

Nexo Web

Readable Nexo components compiled to JavaScript, HTML and scoped CSS. Local state updates the DOM directly, with no virtual DOM or React dependency.

Try two Counters · Try M2 composition and routing · Language and lifecycle reference

M1 and M2 run through the Python CLI. The Rust driver does not compile browser components. The existing WASI command nexo build --target web keeps its established behavior.

One readable component

A component combines local state, an action written with fn, a view and a style. This is the exact acceptance example compiled into the demo.

counter.nexo · M1
use nexo.web

pub component Counter:
    state count: int = 0

    fn increment():
        count += 1

    view:
        main:
            h1("Nexo Web")
            p("Count: {count}")
            button("+", on_click: increment)

    style:
        main {
            padding: 24px;
        }

Every instance gets fresh typed state. Clicking the native button batches state changes and updates only bindings that depend on them, skipping unchanged rendered values. Text becomes text nodes, so markup in strings is displayed safely. Destroying a mount removes its listeners and subscriptions.

Actions currently support local assignments; state types are int, str and bool. Expressions include literals, state reads, interpolation, checked integer arithmetic and string concatenation. Unsupported syntax and reserved words used as state/action names produce a diagnostic.

From readable source to the browser

  1. Nexo Web source

    Components, state, views and styles.
    Pages, layouts and owner-scoped context: experimental M2.

  2. Nexo compiler

    Parse → typed component AST → binding dependencies → DOM instructions + scoped CSS.

    Static bindings have no subscription. Static markup extraction is future optimization.

  3. Browser

    External JavaScript + HTML + CSS. Direct DOM updates; independent owners and cleanup.

React offers component composition; Solid demonstrates fine-grained updates; Svelte moves work into compilation; Vite supplies development tooling. Nexo Web pursues those useful properties with native Nexo syntax. Nexo Web remains much smaller: composition is implemented in experimental M2; optional Vite development and conservative HMR are implemented in M4. No comparative performance claim has been measured.

Compose screens with M2

Components take typed, read-only scalar properties. Project imports use qualified use names and pub exports. A component projects nested content through slot(); a layout owns persistent shared structure. Each provider creates its own context instance; inject() resolves the nearest provider.

Pages declare explicit paths and typed parameters. M2 uses fragment URLs such as #/users/7, so the working demo runs on static hosting. Local anchors, back/forward navigation, nested layout persistence, page metadata, not-found and navigation error pages are supported. Navigation focuses the new page content.

composition/app.nexo · M2
use nexo.web
use session
use ui.widgets

pub layout Shell:
    provide session.Visits
    visits = inject(session.Visits)
    state opens: int = 0

    fn open():
        opens += 1

    view:
        header:
            h1("Nexo Web M2")
            p("Shared visits: {visits.count}; layout clicks: {opens}")
            button("Layout +", on_click: open)
            nav:
                a("Home", href: "/")
                a("User 7", href: "/users/7")
        slot()

pub layout Details:
    layout = Shell
    state opens: int = 0

    fn open():
        opens += 1

    view:
        section:
            h2("Persistent nested layout")
            p("Nested layout clicks: {opens}")
            button("Nested +", on_click: open)
            slot()

pub page Home:
    path = "/"
    layout = Shell
    title = "Nexo Web — Home"
    description = "A compiled Nexo component, layout and context example."
    visits = inject(session.Visits)
    state label: str = "Local count"

    fn rename():
        label = "Updated count"

    view:
        main:
            widgets.Card(heading: label):
                p("Shared in slot: {visits.count}")
                button("Shared +", on_click: visits.increment)
                button("Rename", on_click: rename)
                widgets.Counter(label: label)

pub page User(id: int):
    path = "/users/{id}"
    layout = Details
    title = "Nexo Web — User {id}"
    visits = inject(session.Visits)

    view:
        main:
            h2("User {id}")
            p("Shared on another page: {visits.count}")
            button("Shared +", on_click: visits.increment)

pub page NotFound:
    not_found = true
    layout = Shell
    title = "Nexo Web — Not found"

    view:
        main:
            h2("Page not found")
            a("Return home", href: "/")

pub page Failure:
    error = true
    title = "Nexo Web — Error"

    view:
        main:
            h2("Unable to render this page")

Shared layout state survives navigation through a common layout prefix. Page state resets when leaving a page or changing parameters. Context updates batch across owners. Slots retain caller bindings and CSS, while their listeners and subscriptions are cleaned up with the receiving component.

Props and route parameters support int, str and bool. Layouts require exactly one slot and have no props yet. Local project modules/CSS are supported; package imports, keyed-list reconciliation and SSR remain future work. Error pages handle mount/navigation failures, not arbitrary event exceptions.

Scoped CSS

Write standard CSS selectors and declarations. The compiler emits an external stylesheet with native @scope boundaries. Custom properties and media/container/supports queries work. Use a modern browser with CSS scope support.

Local @import "./card.css"; is expanded into the component scope in M2. Remote imports and resource functions such as url() and image-set(), global at-rules, CSS escapes and minification remain unsupported. Styles are component-owned; no inline style is needed.

M3: typed asynchronous data

load owns a reactive GET; mutation owns an explicit POST, PUT, PATCH or DELETE. Both use nonblocking browser fetch, exact JSON contracts and visible loading/error states. A successful mutation reloads its explicitly named reads.

Try the read-only M3 demo. It fetches a real static JSON file. Writes are disabled there; run the complete local project below to test CSRF-protected creation and invalidation.

data/app.nexo · M3
use nexo.web

pub type Product:
    id: int
    name: str

pub type NewProduct:
    name: str

pub component App(endpoint: str = "/api/products", writable: bool = true):
    load products = api.get(
        endpoint,
        as: list[Product],
        timeout_ms: 5000,
        retries: 1,
        cache_ms: 1000
    )

    mutation create = api.post(
        endpoint,
        body: NewProduct(name: "Nexo handbook"),
        as: Product,
        invalidate: [products]
    )

    view:
        main:
            h1("Nexo Web — typed data")
            if products.loading:
                p("Loading...", role: "status")
            elif products.error != none:
                p("{products.error.kind}: {products.error.message}", role: "alert")
                button("Retry", on_click: products.reload)
            elif products.ready:
                ul:
                    for product in products.data:
                        li(product.name)
            button("Reload", on_click: products.reload)
            button("Cancel read", on_click: products.cancel)
            button("Create product", on_click: create.run, disabled: not writable or create.loading)
            if create.loading:
                p("Saving...", role: "status")
            elif create.error != none:
                p("{create.error.kind}: {create.error.message}", role: "alert")
            elif create.success:
                p("Created: {create.data.name}", role: "status")

    style:
        main { max-width: 48rem; margin: 2rem auto; padding: 1rem; font-family: system-ui; }
        button { margin: 0.25rem; padding: 0.5rem; }
        button:focus-visible { outline: 3px solid currentColor; outline-offset: 2px; }

Data is available only inside a ready or mutation success branch. Errors expose kind, message and HTTP status. reload, cancel and mutation run are explicit operations. Views support conditions and immutable list snapshots; replacing a list resets its child state. Keyed reconciliation remains future work.

GET supports bounded timeouts/retries, consumer-aware deduplication and opt-in memory caching. Requests and cache belong to one mounted application; unmount cancels its work. Changing user/session requires destroying and remounting the root. JSON int values must fit the safe wire integer range; use str for larger identifiers.

Requests allow same-origin paths only, with HTTPS in production. Writes require a server-injected CSRF token and backend Origin/token validation. Credentials use same-origin cookies. M4: develop with Vite

Vite supplies the optional local development server and module transport. The Nexo compiler still owns parsing, types and browser code. No React wrapper or TypeScript application syntax is involved.

New project · M4
python -m nexo web new my-app
cd my-app
npm ci
python -m nexo web dev app.nexo
# Open the loopback URL printed by the command.
python -m nexo web check --json app.nexo
python -m nexo web audit --security --json app.nexo
python -m nexo web build app.nexo --sourcemap -o dist
python -m nexo web preview dist

Install Nexo first. Development requires Node 22.12 or 24+ and locked Vite 8.3.5; npm installation is explicit. Existing repository examples use npm ci --prefix nexo/web_tools followed by python -m nexo web dev examples/web/counter.nexo. Build, check, audit and preview do not need Node.

CSS-only updates keep the current UI and state when generated JavaScript and mapped line positions stay unchanged. Logic edits destroy and remount the application: counters, context and requests reset. Compile errors retain the last valid UI and display a keyboard-readable text diagnostic. The working Counter is the same source used by the scaffold and HMR tests.

Dev binds 127.0.0.1, checks Host/Origin, and does not serve project .env files, public directories or arbitrary source paths. It loads no project Vite configuration. Preview serves only built assets. Neither is production hosting or a backend API proxy; keep using the M3 local API example for complete request/mutation testing.

Find errors in the editor and browser

web check --json now includes source statement columns and snippets. build --sourcemap emits deterministic line-level JavaScript maps with embedded Nexo sources; omit maps when source publication is not intended. CSS maps and precise expression stepping remain unsupported.

Configure a frontend editor to run python -m nexo web lsp. It offers unsaved-entry diagnostics, local definitions/hover, outline and canonical browser completions. The existing core nexo lsp is unchanged. Browser formatting, cross-file navigation and unsaved imported-buffer overlays are not implemented.

Review browser security boundaries

web audit --security applies compiler capability checks and flags credential-like literals and opt-in cache requiring identity review. Findings are redacted; no findings does not prove security. Backend authorization remains explicitly unassessed. The report explains Shield memory dispatch and bounded loopback ingress limits; it does not run Shield in a browser or turn its listener into production hosting.

M4 semantics, limits and troubleshooting. Development features are tested locally with real Vite and Chromium; no comparative performance or production-readiness claim is made.

M5: optimized releases and measured quality

build --release minifies and tree-shakes the application with pinned Vite, emits hashed assets and SRI HTML, and records checksums and sizes in nexo-manifest.json. This remains client-rendered static hosting; it is not SSR or static page generation. Ordinary builds remain available without Node.

Accessibility and safe deployment

Source audit flags missing control names, positive tabindex and hidden interactive controls. Pinned axe-core tests the rendered example under WCAG A/AA and best-practice rules, with separate keyboard/status/focus checks. Automated scans cover the tested states and browser; they do not certify every application or replace assistive-technology review.

The Nginx example has a locally verified non-root, read-only container, restrictive headers, static health, rate limits and privacy-minimized access logs. It does not provide backend APIs, authentication or production TLS: use a trusted HTTPS edge and independently authorize backend resources. Shield's bounded profiles remain backend tools. Choose hosting by budget and reliability; a simple static app usually does not need Kubernetes.

Optional --observe emits allowlisted local browser events for mounts, requests and navigation, with phases and timing/error metadata. No collector, upload, persistence, raw messages, payloads or URLs are included. Default builds emit none. Operators must explicitly integrate and protect any external monitoring.

Build into a dedicated directory: unrelated files are preserved by refusing replacement. Source maps are opt-in and expose source. M5 reference and limitations. M6 features remain future work.

Security and accessibility

Browser compilation rejects server imports, arbitrary calls, HTML injection, script elements, unsafe URL attributes and inline event code. Generated demo assets use a restrictive CSP. Never put secrets in a browser bundle. Visibility checks never replace server authorization.

Shield remains a backend security foundation: use supported policy, authentication, authorization, rate-limit and CSRF controls. Its bounded loopback ingress is not a persistent production web server. Production needs HTTPS, secure HttpOnly sessions and a separately validated backend. OWASP ASVS 5.0 guides future reviews; M1–M5 are not a certification.

Native elements support keyboard interaction. Authors remain responsible for meaningful labels, focus, headings, contrast and ARIA. The compiler does not yet perform an accessibility audit.
