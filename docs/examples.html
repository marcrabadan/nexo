Calculate an invoice.

Give a price and quantity a name, calculate the tax and print the result. A currency such as EUR makes an amount a money value, so you can read the calculation in the same terms as an invoice.

  1. Name your values. price and quantity hold the inputs.
  2. Calculate the result. * multiplies, and 21% expresses the tax rate.
  3. Print a message. A name inside { } inserts its value into the text.

After installing Nexo, save this as invoice.nexo in the repository root and run:

From the repository root
.venv/bin/nexo invoice.nexo

Try a change. Set quantity to 3. Before running it again, predict the subtotal.

New to programming? Start with the guided lessons →

invoice.nexo
price = 49.90 EUR
quantity = 2
subtotal = price * quantity
vat = subtotal * 21%

print("Subtotal: {subtotal}")
print("VAT: {vat}")
print("Total: {subtotal + vat}")
Output

VAT: 20.96 EUR
Total: 120.76 EUR

Totals per region from a CSV file, with where, group by, sum, sort by, take and save.

## Sales report: totals per region from a CSV file.
## Shows a pipeline with where, group by, sum, sort by, take and save.

sales = read("data/sales.csv")

print("Rows read: {sales |> count}")

by_region = sales
  |> where amount > 0
  |> group by region
  |> sum amount
  |> sort by amount desc

print("Sales per region:")
for row in by_region:
    print("  {row["region"]}: {row["amount"]} EUR")

best = by_region |> take 1
print("Best region: {best[0]["region"]}")

laptops = sales |> where product == "laptop" |> map amount
print("Laptops sold: {len(laptops)}, average price {round(laptops |> avg, 2)} EUR")

refunds = sales |> where amount < 0 |> count
print("Refunds: {refunds}")

by_region |> save("sales_summary.out.csv")
print("Saved sales_summary.out.csv")

Accounts guarded by expect, ensure and old(); a broken contract is an error that can be handled.

examples/bank.nexo
## Bank accounts with contracts: expect, ensure and old() guard every
## operation, and a broken contract is an error that can be handled.

type Account:
    owner: str
    balance: money

fn deposit(account: Account, amount: money):
    expect amount > 0.00 EUR
    ensure account.balance == old(account.balance) + amount

    account.balance += amount

fn transfer(source: Account, target: Account, amount: money):
    expect amount > 0.00 EUR
    expect source.balance >= amount
    ensure source.balance + target.balance == old(source.balance + target.balance)

    source.balance -= amount
    target.balance += amount

ana = Account(owner: "Ana", balance: 100.00 EUR)
luis = Account(owner: "Luis", balance: 20.00 EUR)

deposit(ana, 50.00 EUR)
transfer(ana, luis, 70.00 EUR)
print("{ana.owner}: {ana.balance}")
print("{luis.owner}: {luis.balance}")

try:
    transfer(luis, ana, 500.00 EUR)
else e is ContractBroken:
    print("Rejected: {e.message}")

try:
    deposit(ana, -5.00 EUR)
else e is ContractBroken:
    print("Rejected: {e.message}")

test "a transfer keeps the total":
    a = Account(owner: "A", balance: 10.00 EUR)
    b = Account(owner: "B", balance: 0.00 EUR)
    transfer(a, b, 4.00 EUR)
    assert a.balance == 6.00 EUR
    assert b.balance == 4.00 EUR

test "cannot transfer more than the balance":
    a = Account(owner: "A", balance: 1.00 EUR)
    b = Account(owner: "B", balance: 0.00 EUR)
    assert transfer(a, b, 2.00 EUR) fails

What you’ll learn: Records, methods and decisions

Read the related language guide →

Records with methods, an enum, a trait and match with guards.

examples/grades.nexo
## Grade book: records with methods, an enum, match with guards and a trait.

trait Describable:
    fn describe(self) -> str

type Grade:
    Excellent
    Good
    Pass
    Fail

type Student is Describable:
    name: str
    scores: list[int]

    fn average(self) -> float:
        return self.scores.sum() / len(self.scores)

    fn describe(self) -> str:
        return "{self.name} ({len(self.scores)} exams)"

fn grade(avg: float) -> Grade:
    match avg:
        a if a >= 9: return Excellent
        a if a >= 7: return Good
        a if a >= 5: return Pass
        _: return Fail

fn label(g: Grade) -> str:
    match g:
        Excellent: return "excellent"
        Good: return "good"
        Pass: return "pass"
        Fail: return "fail"

students = [
    Student("Ana", [9, 10, 9]),
    Student("Luis", [6, 7, 5]),
    Student("Eva", [4, 3, 6]),
    Student("Marc", [8, 7, 9])
]

for s in students:
    avg = s.average()
    print("{s.describe()}: {round(avg, 1)} -> {label(grade(avg))}")

passed = students |> where grade(it.average()) != Fail |> count
print("Passed: {passed} of {len(students)}")

ranking = students |> sort by it.average() desc |> map name
print("Ranking: {ranking}")

test "grades follow the average":
    assert grade(9.5) == Excellent
    assert grade(7.0) == Good
    assert grade(4.9) == Fail

test "average of a student":
    assert Student("X", [5, 7]).average() == 6.0

Eva (3 exams): 4.3 -> fail

Passed: 3 of 4
Ranking: ["Ana", "Marc", "Luis", "Eva"]

A web API with a database and ask, written in Nexo alone. Its tests fake the AI, so they run without a key.

examples/shop_api/shop.nexo
# A shop's web API with a database and AI, written in Nexo alone.
# Run it with
#     SHOP_JWT_KEY=... ANTHROPIC_KEY=... nexo shop.nexo
# and test it, with the AI faked, with `nexo test shop.nexo`.
use nexo.db

db = connect("shop.db")
tokens = jwt(key: secret("SHOP_JWT_KEY"))

ai:
    provider = "anthropic"
    model = "claude-opus"
    key = secret("ANTHROPIC_KEY")

@table
type Product:
    id: id
    name: str @unique
    price: decimal

@table
type Review:
    id: id
    product: ref Product
    text: str
    tone: str
    score: int

type NewProduct:
    name: str
    price: decimal

type NewReview:
    text: str

type Opinion:
    tone: "positive" | "negative" | "neutral"
    score: 1..5

## What the AI thinks of a review: its tone and a score from 1 to 5.
fn opinion(text: str) -> Opinion!:
    o: Opinion = ask("Analyse this review of a product", text, creativity: low)?
    return o

## A short summary of the reviews of a product.
fn summary(reviews: list[Review]) -> str!:
    if len(reviews) == 0:
        return "No reviews yet."
    texts = reviews |> map it.text
    return ask("Summarise these reviews in one sentence", texts, max: 40 words)?

server shop:
    port = 8080
    auth = tokens

    @public
    post "/login"(name: str):
        return {"token": tokens.sign({"sub": name, "role": "admin"}, expires: 1h)}

    @public
    get "/products"():
        return db.Product |> sort by name

    @public
    get "/products/{id}"(id: int):
        return db.Product.find(id: id)?

    @role("admin")
    post "/products"(product: NewProduct):
        return db.Product.add(name: product.name, price: product.price)

    @public
    @limit(10 per minute per ip)
    post "/products/{id}/reviews"(id: int, review: NewReview):
        product = db.Product.find(id: id)?
        o = opinion(review.text)?
        return db.Review.add(product: product, text: review.text, tone: o.tone, score: o.score)

    @public
    get "/products/{id}/summary"(id: int):
        product = db.Product.find(id: id)?
        reviews = db.Review |> where product == product
        scores = reviews |> map it.score
        var average = 0.0
        if len(scores) > 0:
            average = float(scores |> sum) / len(scores)
        return {"product": product.name, "reviews": len(scores), "score": average, "summary": summary(reviews)?}

test "products need an admin":
    try:
        http.post("{shop.url}/products", {"name": "Lamp", "price": 25}, retries: 0)
    else e is HTTPError:
        assert e.message.ends_with("401 Unauthorized")
    login = http.post("{shop.url}/login?name=ana", none).json()
    headers = {"Authorization": "Bearer {login["token"]}"}
    lamp = http.post("{shop.url}/products", {"name": "Lamp", "price": 25.50}, headers: headers)
    assert lamp.status == 201
    assert lamp.json()["name"] == "Lamp"
    assert http.get("{shop.url}/products").json()[0]["price"] == 25.5

test "reviews are analysed by the AI":
    fake ask returns Opinion(tone: "positive", score: 5)
    login = http.post("{shop.url}/login?name=ana", none).json()
    headers = {"Authorization": "Bearer {login["token"]}"}
    chair = http.post("{shop.url}/products", {"name": "Chair", "price": 80}, headers: headers).json()
    review = http.post("{shop.url}/products/{chair["id"]}/reviews", {"text": "Comfortable!"}).json()
    assert review["tone"] == "positive" and review["score"] == 5
    fake ask returns "Buyers love it."
    s = http.get("{shop.url}/products/{chair["id"]}/summary").json()
    assert s["summary"] == "Buyers love it." and s["reviews"] == 1 and s["score"] == 5.0

test "a missing product is a 404":
    try:
        http.get("{shop.url}/products/999", retries: 0)
    else e is HTTPError:
        assert e.message.ends_with("404 Not Found")
$ SHOP_JWT_KEY=... nexo test shop.nexo

✓ reviews are analysed by the AI
✓ a missing product is a 404

The standard library in one program: a regex checks the email, only the Argon2id hash of the password is kept, the time is shown in another zone, a template is filled with render and signed, and log hides the @private field.

examples/signup.nexo
## Sign-ups: checks an email with a regular expression, stores only the
## hash of the password, signs the welcome letter and logs the account
## with its @private fields hidden. Shows the standard library.

type Account:
    name: str
    email: str
    password: str @private
    since: time

    keep = 5 years after since
    purpose = "logging in"

email_format = regex("^([a-z0-9.]+)@([a-z0-9]+)\\.([a-z]+)$")

fn sign_up(name: str, email: str, plain: str, moment: time) -> Account!:
    if not email_format.matches(email):
        fail("\"{email}\" is not a valid email")
    if len(plain) < 8:
        fail("the password needs at least 8 characters")
    return Account(name: name, email: email, password: password.hash(plain), since: moment)

fn log_in(account: Account, plain: str) -> bool:
    return password.check(plain, account.password)

opening = time(2026, 10, 26, 9, 30, zone: "Europe/Madrid")
attempts = [
    ["Ana", "ana@mail.com", "correct horse"],
    ["Luis", "luis(at)mail.com", "battery staple"],
    ["Eva", "eva@mail.com", "short"]
]

var accounts = []
for a in attempts:
    try:
        accounts.add(sign_up(a[0], a[1], a[2], opening))
        print("signed up: {a[0]}")
    else e:
        print("rejected {a[0]}: {e.message}")

ana = accounts[0]
print("Ana logs in: {log_in(ana, "correct horse")}, with a wrong password: {log_in(ana, "horse")}")
print("Ana in New York: {ana.since.to_zone("America/New_York")}")
print("parts of the email: {email_format.groups(ana.email)}")
log(ana)

letter = render("data/welcome.txt", name: ana.name, email: ana.email, since: ana.since.date)
print(letter, end: "")
pair = keypair.new()
signature = sign(letter, pair.private)
print("signed: {verify(letter, signature, pair.public)}, changed: {verify(letter + "!", signature, pair.public)}")

test "a bad email is rejected":
    assert sign_up("X", "x@", "long enough", opening) fails

test "only the hash is kept":
    a = sign_up("X", "x@mail.com", "long enough", opening)
    assert a.password != "long enough"
    assert log_in(a, "long enough")

# runs (AWS, Azure, GCP and Kubernetes) and how it gets there.
#     nexo shop.nexo                serves it on port 8080
#     nexo test shop.nexo           runs its tests
#     nexo plan / nexo apply        deploys it to the four targets
#     nexo ci run --yes             builds its image and deploys it
#     nexo ci export github         writes the workflow that does the same

    express_shipping = 20%

    item: str
    quantity: int

## The price of shipping an order: express for some users (a flag).
fn shipping(order: Order, user: str) -> money:
    if flag("express_shipping", user):
        return 4.90 EUR
    return 2.50 EUR + 0.10 EUR * order.quantity

test "shipping grows with the quantity":
    assert shipping(Order(item: "tea", quantity: 1), "nobody") <= shipping(Order(item: "tea", quantity: 3), "nobody")

server shop:
    port = 8080

    @public
    get "/health":
        return {"ok": true}

    @public

## a bad one goes to the dead letters after its retries, clicks are counted

use nexo.stream

flags:
    free_shipping = 25%
    new_banner = users where country == "ES"

type User:
    id: int
    country: str

type Order:
    id: int
    user: int
    total: decimal

fn shipping(order: Order) -> money:

fn process(order: Order):
    if order.total <= 0:

when kafka("orders") as msg, key: msg.json()["id"]:

  |> group by page

Databases without SQL strings

With use nexo.db, @table types are the schema, and ref and many are the relations between them. A pipeline on a table, such as db.Order |> where amount > 100, becomes one parameterised SQL query on SQLite.

Everything inside db.transaction: is kept or undone together: the second customer breaks @unique, so the order added before it is rolled back too. nexo db diff and nexo db migrate keep the database in step with the types.

orders.nexo
use nexo.db

db = connect("shop.db")

@table
type Customer:
    id: id
    name: str
    email: str @unique
    orders: many Order

@table
type Order:
    id: id
    customer: ref Customer
    amount: float

ana = db.Customer.add(name: "Ana", email: "ana@mail.com")
db.Order.add(customer: ana, amount: 49.9)
db.Order.add(customer: ana, amount: 150.0)

large = db.Order |> where amount > 100 |> map it.amount
print(large)
print(ana.orders.count(), ana.orders |> map it.amount |> sum)

try:
    db.transaction:
        db.Order.add(customer: ana, amount: 1.0)
        db.Customer.add(name: "Copy", email: "ana@mail.com")
else e:
    print(e.message)
print(db.Order.count())

A web API in a block

A server block has typed routes: {n} arrives as an int and a body as an Item, and anything else is a 400. Returning a number answers with that status, and errors become status codes.

auth = jwt(...) protects every route that is not @public, and @role asks for a role in the token. Under nexo test the server answers on a free port, at shop.url.

api.nexo
tokens = jwt(key: password.generate(32))

type Item:
    name: str
    price: decimal

items = [Item(name: "pen", price: 1.50)]

server shop:
    port = 8080
    auth = tokens

    @public
    get "/items/{n}"(n: int):
        if n >= len(items):
            return 404
        return items[n]

    @role("admin")
    post "/items"(item: Item):
        return item

test "routes answer JSON":
    assert http.get("{shop.url}/items/0").json()["name"] == "pen"

test "errors become status codes":
    try:
        http.get("{shop.url}/items/9", retries: 0)
    else e is HTTPError:
        print(e.message.replace(shop.url, ""))
    try:
        http.post("{shop.url}/items", {"name": "cup", "price": 2}, retries: 0)
    else e is HTTPError:
        print(e.message.replace(shop.url, ""))

AI as a function call

ask sends an instruction and an input to the configured model (Anthropic, OpenAI or Ollama, set up with nexo ai setup or an ai: block). With a declared type the answer is that type, checked field by field, so score is always between 1 and 5.

fake ask returns ... replaces the model inside a test, so tests run offline and without a key. @tool functions and agent blocks let the model call your code.

reviews.nexo
type Opinion:
    tone: "positive" | "negative" | "neutral"
    score: 1..5

fn classify(review: str) -> Opinion!:
    o: Opinion = ask("Analyse this review", review)?
    return o

fn summary(text: str) -> str!:
    return ask("Summarise this text", text, max: 20 words, creativity: low)?

test "a typed answer":
    fake ask returns Opinion(tone: "positive", score: 4)
    assert classify("Great!").score == 4

test "a short summary":
    fake ask returns "A short text."
    assert summary("A very long text") == "A short text."

Secrets that never leak

The algorithms are chosen for you: Argon2id for password.hash, AES-256-GCM for encrypt and Ed25519 for sign. There is nothing to configure wrongly.

secret("NAME") reads a secret from the environment. It can be passed where it is needed, such as a key or a header, but never printed, logged or written to a file. A key written in the code is a compile error.

secrets.nexo
stored = password.hash("hunter2")
print(password.check("hunter2", stored), password.check("hunter3", stored))

k = key.new()
hidden = encrypt("Ana's card", k)
print(decrypt(hidden, k))

pair = keypair.new()
signature = sign("contract v1", pair.private)
print(verify("contract v1", signature, pair.public), verify("contract v2", signature, pair.public))

db_pass = secret("DB_PASSWORD")
print("the password is {db_pass}")
$ nexo secrets.nexo
true false
Ana's card
true false
Error in secrets.nexo, line 13:
  print("the password is {db_pass}")
                          ^^^^^^^
A secret cannot be shown or turned into text. Pass the secret only where it is needed (key: ..., a connect password, an http header); never to print, str() or a file.

Dates, text and data

Dates and instants know their time zone: adding an hour across the change to summer time in Madrid gives 03:30, not 02:30. Durations such as 7 days and 1h are literals.

regex leaves out lookarounds and backreferences, so a pattern matches the same in both implementations. convert turns records into CSV or JSON, and changing currency needs an explicit rate.

dates.nexo
d = date(2026, 10, 24)
print(d + 7 days, d.weekday)
t = time(2026, 3, 29, 1, 30, zone: "Europe/Madrid")
print(t + 1h)
print(t.to_zone("America/New_York"))

email = regex("(\\w+)@(\\w+)\\.com")
print(email.groups("write to ana@mail.com today"))
print(regex("[0-9]+").find_all("ab 42 cd 7"))

Pipelines that are ordinary code

The steps of a pipeline are Nexo code with test(), run, build_image, approve and apply, and a variable set in one step is seen by the next.

nexo ci run runs it on your machine, asking before each step (--yes runs the steps without those prompts). nexo ci export github, gitlab, azure or jenkins writes the file that runs the same steps in CI.

app.nexo
fn total(prices: list[int]) -> int:
    return prices |> sum

test "the total adds the prices":
    assert total([2, 3]) == 5

pipeline main:
    trigger push to main
    version = "1.4.0"

    step checks:
        test()

    step build:
        image = "shop:{version}"
        run("echo building {image}")

    step prod:
        approve(by: ["ana@shop.example", "luis@shop.example"])
        print("deploying", image)

    after success:
        print("v{version} is live")

Streams are another source

when kafka("orders") as msg handles each message. A message that fails is tried again and then goes to the dead letters, and a key makes sure the same order is processed once.

A stream also starts a pipeline: window 1m, sliding and session group its messages by time. This edition has a local broker, so tests send messages with .send.

stream.nexo
use nexo.stream

type Order:
    id: int
    total: int

fn process(o: Order):
    if o.total < 0:
        fail("negative total")
    print("order", o.id, o.total)

when kafka("orders") as msg, key: msg.json()["id"]:
    o: Order = validate(msg.json(), as: Order)?
    process(o)?

fn publish(row):
    print("per minute", row)

kafka("clicks")
  |> window 1m
  |> group by page
  |> count
  |> each publish

Feature flags in the code

A flags block declares each flag once: on or off, a percentage of users or the users that match a condition. flag(name, user) reads it.

A percentage is stable: the same user always gets the same answer, so a feature can grow from 10% to 100% without anyone seeing it come and go. nexo flags set changes a flag while the program runs, without a new release, and records who changed it.

flags.nexo
type User:
    id: int
    country: str

flags:
    new_checkout = 10%
    dark_mode = users where country == "ES"
    payments_v2 = off

ana = User(id: 7, country: "ES")
luis = User(id: 8, country: "FR")
print(flag("payments_v2"))
print(flag("dark_mode", ana), flag("dark_mode", luis))

var count = 0
for i in range(1, 1001):
    if flag("new_checkout", User(id: i, country: "ES")):
        count += 1
print("{count} of 1000 users see the new checkout")
print(flag("new_checkout", ana) == flag("new_checkout", ana))

Personal data, kept by rule

Fields marked @personal or @private say what data is personal. @private fields are encrypted in the database and hidden by log, and keep erases old rows by itself. A personal type without keep and purpose is a warning, and an error in a release build.

privacy.export, erase and restrict answer a person's requests, and nexo privacy report lists what personal data the program holds, why, and who can read it.

customers.nexo
use nexo.db

db = connect("shop.db", key: secret("DB_KEY"))

@table
type Customer:
    id: id
    name: str @personal
    email: str @personal
    national_id: str @private
    last_activity: date

    keep = 5 years after last_activity
    purpose = "billing and shipping"

ana = db.Customer.add(name: "Ana", email: "ana@x.com", national_id: "123A", last_activity: date(2026, 1, 2))

privacy.erase(ana)
print(db.Customer.count())
