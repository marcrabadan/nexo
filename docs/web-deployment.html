Optimized releases and measured quality

build --release minifies and tree-shakes the application with pinned Vite, emits hashed assets and SRI HTML, and records checksums and sizes in nexo-manifest.json. This remains client-rendered static hosting; it is not SSR or static page generation. Ordinary builds remain available without Node.

Release workflow
npm ci --prefix nexo/web_tools
python -m nexo web audit --security --accessibility --json examples/web/production/app.nexo
python -m nexo web build examples/web/production/app.nexo --release -o dist
python -m nexo web preview dist
python scripts/web/measure.py --output /tmp/web-quality.json --check

Accessibility and safe deployment

Source audit flags missing control names, positive tabindex and hidden interactive controls. Pinned axe-core tests the rendered example under WCAG A/AA and best-practice rules, with separate keyboard/status/focus checks. Automated scans cover the tested states and browser; they do not certify every application or replace assistive-technology review.

The Nginx example has a locally verified non-root, read-only container, restrictive headers, static health, rate limits and privacy-minimized access logs. It does not provide backend APIs, authentication or production TLS: use a trusted HTTPS edge and independently authorize backend resources. Shield's bounded profiles remain backend tools. Choose hosting by budget and reliability; a simple static app usually does not need Kubernetes.

Local production-example qualification records verified disposable TLS, burst limiting/recovery, container restart and a dated image scan. The image pins signed Alpine security fixes; CI rejects HIGH/CRITICAL findings. Firefox/WebKit checks are configured but support requires actual passing results. These local checks do not qualify a real backend, public TLS renewal, business workload or production SLO.

Optional --observe emits allowlisted local browser events for mounts, requests and navigation, with phases and timing/error metadata. No collector, upload, persistence, raw messages, payloads or URLs are included. Default builds emit none. Operators must explicitly integrate and protect any external monitoring.

Build into a dedicated directory: unrelated files are preserved by refusing replacement. Source maps are opt-in and expose source. Release reference and limitations. Scalar request-time rendering is available through WSGI; scalar and conditional hydration is available with an explicit flag.

Generate HTML without JavaScript

build --static renders scalar components or finite public pages into HTML and scoped CSS. Literal routes are automatic; enumerate concrete dynamic URLs in a JSON array. Pages support nested layouts, title/description metadata and ordinary links, and work with JavaScript disabled.

Static site workflow
python -m nexo web build examples/web/ssg/app.nexo --static --routes examples/web/ssg/routes.json -o dist
python -m nexo web preview dist

This experimental mode requires a root page at / and origin-root hosting with directory index files. Every dynamic page needs at least one enumerated URL, and rendered links must point to generated pages. The first slice accepts portable ASCII slug segments. The preview serves generated 404.html with HTTP 404; configure that behavior explicitly on your production host.

Actions, events and browser requests are unsupported in static mode; typed records/lists, loops and scoped context are supported. Static mode cannot combine with release optimization, observation or source maps. It does not provide request-time SSR, hydration or a production qualification. Static generation reference and limits.

Render pages per request

python -m nexo web serve examples/web/ssr/app.nexo --port 4174 starts an experimental loopback runner. It compiles source once, then renders typed page URLs on demand without enumeration or browser JavaScript. Page/layout state is fresh for each request. HTML, CSS, GET/HEAD, redirects and 404/500 status pages are supported.

Integrate SSRApplication.from_file(...) from nexo.web_ssr with a synchronous WSGI host to use the rendering interface. The local reference runner does not supply production hosting, authentication, TLS or request limits. Trusted async Python loaders provide checked root-page state; records/lists and fresh scoped context are supported. Browser load/mutation resources are not executed by SSR. Scalar and conditional hydration is available through the explicit option below. Request-time rendering reference and limits.

Attach client behavior to server HTML

python -m nexo web serve examples/web/hydration/app.nexo --hydrate --port 4174 enables experimental scalar hydration, including conditional views. The client validates existing markup before attaching listeners, preserves nodes/focus and pre-hydration input edits, and uses the existing scalar actions and typed input events. A mismatch leaves the server tree intact with no attached behavior.

WSGI integrations can pass hydrate=True to SSRApplication.from_file(...). This mode adds a cached external same-origin module and escaped typed route props; it serializes checked root-page state from explicit trusted async loaders. Lists, context and local full-document navigation are supported; automatic mismatch remounts remain unsupported. Conditional branches retain local state while their choice stays unchanged; switching branches resets only their owned descendants. Preserve compiler comment boundaries in deployed HTML. Without JavaScript, content and native links still work. Hydration state, mismatch and lifecycle reference.

Try examples/web/conditional-hydration/app.nexo with the same serve --hydrate command to exercise nested branches and projected slots. Conditional ownership and transition limits.

Security and accessibility

Browser compilation rejects server imports, arbitrary calls, HTML injection, script elements, unsafe URL attributes and inline event code. Generated demo assets use a restrictive CSP. Never put secrets in a browser bundle. Visibility checks never replace server authorization.

Shield remains a backend security foundation: use supported policy, authentication, authorization, rate-limit and CSRF controls. Its bounded loopback ingress is not a persistent production web server. Production needs HTTPS, secure HttpOnly sessions and a separately validated backend. OWASP ASVS 5.0 guides future reviews; these experimental features are not a certification.

Native elements support keyboard interaction. Authors remain responsible for meaningful labels, focus, headings, contrast and ARIA. Use web audit --accessibility for the supported source checks and test the rendered application with assistive technology.

M6 experimental implementation

Stable-release acceptance criteria track browser qualification, lifecycle, security, hosting and compatibility work. Strict CI rejects skipped or empty M6 runs; this work does not yet change the experimental status.

Static HTML, routed SSG, request-time SSR and hydration now include typed record/list state, scoped context, keyed rows and trusted async server loaders. Explicit adapters add public offline PWA output, import-free numeric WASM in owned Workers, and typed public SSE snapshots.

Run python examples/web/m6/server.py for the integrated example. Public offline output uses build --static --pwa, optionally with --routes. Example and commands; verification and limits. These bounded experimental contracts do not supply production authentication, TLS hosting, streaming SSR or durable messaging.
